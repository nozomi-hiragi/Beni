# ホーム画面

## 目的

タスクを一覧して状況を確認し、新しいタスクを作成したり、各タスクのチャットを開いたりする。

ホームの URL は `/` とする。

## 画面の配置

上部の共通ヘッダーでは、左に「Beni」、右に LLM の利用枠、インストラクション管理、設定をこの順に表示する。その下にタスク作成フォームとタスク一覧を表示する。

## 表示・操作

- ホーム画面にタスク名の入力欄と「タスク作成」ボタンを表示し、その近くにプロジェクト選択のプルダウンを置く。
- プルダウンには既存プロジェクトと「新規プロジェクト作成」を表示する。新規作成を選ぶと、プロジェクト作成ダイアログを開く。
- プロジェクトを選ぶと「プロジェクトを開く」から General チャットのあるプロジェクト詳細へ移動できる。
- タスク名・フェーズ・状態・作成日・更新日を一覧表示する。現行の状態欄は保存状態の `idle`、`completed` を表示し、処理中や回答待ちなどの詳細な状態表示は設計上の要件として残っている。
- 見出しを押すたびに、その列の昇順・降順を切り替える。作成日と更新日は、それぞれ最初に押すと新しい順、もう一度押すと古い順になる。日時不明のタスクはどちらでも末尾に置く。最後に押した列を優先し、同じ値のタスクは直前の並び順を保つ。現行データの初期表示はタスク ID の降順とする。
- タスクを選ぶと、プロジェクト詳細画面でそのタスクのチャットを開く。
- 検出した CLI ごとに利用枠のゲージを表示する。取得できた 5 時間枠の残量を優先し、5 時間枠が未取得なら週間枠を表示する。ゲージにカーソルを合わせるかフォーカスすると、両方の残量とリセット時刻を確認できる。詳細と更新操作は [設定画面](settings.md) を参照。
- タスク名が未入力、またはプロジェクトが未選択の場合は「タスク作成」を押せない。両方そろったときに押せる。
- 「タスク作成」でタスク名を使った要件定義などの初期文書を用意し、作成したタスクのチャットを開く。モデルによる要件整理はユーザーがチャットを送信したときに始まる。
- タスクの識別には内部IDを使う。タスク名の重複は許可する。
- タスクの作成後、プロジェクト詳細画面のタスクチャットで希望を伝えていく。

## 未実装の表示仕様

- 状態は「処理中」「回答待ち」「確認待ち」「停止中」「エラー」「完了」を表示する。初期表示では、回答待ち・確認待ち・ユーザーの対応が必要なエラーを優先し、それぞれ新しいタスクから並べる。
- 検索の設計は [タスク検索の仕様](../features/task-search.md) を参照。
