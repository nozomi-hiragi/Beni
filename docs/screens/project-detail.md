# プロジェクト詳細画面

## 目的

ユーザーが一つの画面で、希望の入力、指示書と計画の確認、作業中の質問への回答、結果の確認を行う。細部を常に追う必要はなく、進捗・判断が必要なこと・こだわりへの対応を確認できるようにする。

## URL と画面の復元

プロジェクト詳細画面の URL は `/project/<プロジェクト ID>` とする。タスクのチャットを選択した場合は、`?task=<タスク ID>` で選択中のタスクを指定できる。指定されたタスクは対象プロジェクトに属するものだけを開く。

URL を直接開いたときや再読み込みしたときは、指定されたプロジェクトとタスクを復元する。ブラウザーの戻る・進む操作でも URL に対応する画面と選択を表示する。存在しないプロジェクトや、不正・存在しない・別プロジェクトのタスクが指定された場合は、別の内容を指定されたものとして表示せず、その状態を分かるようにする。

## 画面構成

プロジェクト詳細画面の中で、タスクに対応するチャットとプロジェクト共通の `General` タブを切り替えて使う。最上部のメニューバーにはプロジェクト名を表示し、その左にホームへ戻るアイコンボタン、右にプロジェクト設定ボタンを置く。作業領域は左にチャット、右にプレビューを並べ、それぞれの上部にタブを置く。ターミナルはチャットの下に横長に置き、プレビューは右側で縦に広く使う。

メニューのホームと設定のアイコンは、大きさや線の表現をそろえる。

- **チャット**：タスクに対応するチャットと、タスクに対応しないジェネラルなチャットを扱う。ユーザーは希望や回答、追加指示、フィードバックを入力し、LLM からの質問もここに表示する。
- **プレビュー**：チャットと左右に並べ、指示書や実装計画などの Markdown を確認できる。ファイルツリーから選択したファイルもここで表示する。プレビューはタブで切り替える。タブの左にファイルツリーボタンを置き、押すとプレビュー領域の左側からファイルツリーが現れる。もう一度押すと閉じる。
- **ツリー**：チャットタブの左に固定したボタンで、チャット領域の左側にタスクツリーを開閉する。プレビュータブの左のボタンも固定し、開いたファイルのタブが増えたら右側のタブ領域を横スクロールする。チャットタブも同様に横スクロールする。タスクのタブとツリーの項目にはタスク名を表示する。タスクタブを右クリックし「リネーム」を選ぶと、そのタブ上で名前を編集できる。Enterで保存し、Escで取り消す。日本語入力中の変換確定は編集を続ける。タスクタブで「削除」を選ぶと、対象のタスク名と削除範囲を示す確認ダイアログを開く。OKでタスク・文書・タスク会話を削除し、キャンセルで元の画面に戻る。タブの × は表示を閉じる操作として扱う。タスクやファイルを選んだとき、またはツリーの外側を押したときはツリーを閉じる。フォルダの展開・折りたたみでは閉じない。各タブには閉じるボタンを置き、表示中のタブを閉じたら残っているタブへ切り替える。独立したツリー領域は置かない。
- **ターミナル**：チャットの下に置き、複数のターミナルを共通のタブで切り替える。共通タブバーには左側と右側それぞれにボタンを配置できるようにする。左側をツリー、右側を追加に使う。追加ボタンは最後のタブのすぐ右に続けて置き、タブ列と一緒に横スクロールする。ターミナルではツリーボタンを隠して追加ボタンを表示し、チャットやプレビューではツリーボタンを表示して追加ボタンを隠す。ツリーはデータを受け取って表示する共通部品とする。作業場所でコマンドを実行し、出力を確認できるようにする。シェルはバックエンド側で実行する。操作権とシェルの存続は [ターミナル仕様](../features/terminal.md) を参照する。
- **フェーズインジケーター**：タスクチャット内の上部に配置し、「要件定義」「仕様整理」「実装手順」「実装中」「反省会」の現在地を示す。準備中はインジケーターの右側に実装担当モデル選択と「開始」を並べる。実装中は「停止」のみ、反省会は「タスク完了」、完了後は「再開」を表示する。開始の可否と停止の扱いは [タスクのフェーズ操作](../objects/task.md#フェーズの進行) に従う。ジェネラルチャットでは表示しない。準備中はフェーズ名を押すとそのフェーズへ切り替え、対応する会話と Markdown を表示する。実装中・反省会・完了中はフェーズ名で切り替えられない。実装中・完了中はチャット入力欄とモデル選択を表示しない。フェーズが変わっても同じ画面を使い続ける。

## フェーズと文書タブの表示名

フェーズは「要件定義 → 仕様整理 → 実装手順 → 実装中 → 反省会」の順に表示する。最初の3フェーズでは、対応する文書タブにも同じ日本語名を使う。

| フェーズ表示 | 文書タブの表示 | 保存するファイル名 |
| --- | --- | --- |
| 要件定義 | 要件定義 | `requirements.md` |
| 仕様整理 | 仕様整理 | `documents.md` |
| 実装手順 | 実装手順 | `implementation.md` |
| 反省会 | 反省会 | `retrospective.md` |

## 操作の流れ

1. **要件定義**：ユーザーがチャットに希望を順不同で入力する。軽量モデルがタスク名をもとに指示書の作成を開始し、知見を参照して指示書を更新する。不明点はチャットで質問する。作成中にユーザーが追加で伝えた内容も、適宜指示書へ反映する。ユーザーは更新されるプレビューを確認する。
2. **仕様整理**：仕様整理へ切り替えて、整理対象ごとにMDを作り、仕様整理の目次から資料・仕様の分類別にリンクする。[タスク文書の分類](../objects/task.md#仕様整理で作る追加文書)を参照。
3. **実装手順**：要件定義と整理した仕様をもとに、高性能モデルが検討状況や判断理由を示し、実装計画を Markdown で作る。ユーザーは質問に答えたり、追加希望や修正を伝えたりする。
4. **実装中**：選択した実装担当モデルがゴールまで実装・検証を進める。ユーザーは進捗を閲覧し、必要なら停止して実装手順へ戻る。
5. **反省会**：ユーザーが結果を確認し、未達やズレを追求する。手直し・検証とナレッジの整理を行い、「タスク完了」で完了する。完了後も「再開」で同じ反省会を続けられる。
5. **結果と手直し**：完了したら結果を伝える。ユーザーが修正希望を返した場合は、改めて実装計画を作り、確認・実行する流れを繰り返す。

## 質問への回答

質問はチャット内に表示する。選択肢、数値、日付、シークレットなど、専用の入力部品が適したものにはそれを使い、適切な部品がない場合は通常のテキストで聞く。回答待ちの作業は待ち、依存しない作業は並行して進める。回答は計画や作業に反映する。

## モデルの選択

ユーザーがフェーズごとに使う LLM モデルを選び、その選択を記録する。フェーズ切り替え時に、ユーザーの選択を踏まえて、どのモデルがユーザーと対話するかも判断させる。

## 動作の設計方針

- チャット履歴はフェーズが変わっても時系列で残し、フェーズの区切りと発言したモデルを表示する。詳細画面を開き直しても履歴を確認できる。
- Markdown プレビューは現在のフェーズに対応する指示書または実装計画を表示する。切り替え操作で別の文書や過去の版を閲覧できるようにし、現在版と閲覧中の版を区別する。
- チャット入力欄の右下にモデル選択を置き、その右に送信ボタンを配置する。フェーズごとのモデルをここから選べるようにする。切り替えた選択は記録し、進行中の処理にいつ反映するかを画面で示す。
- 質問は種類に応じた入力部品と送信操作を示す。シークレットは伏せて入力し、チャット履歴や Markdown に値を表示しない。保存や外部への受け渡しは、接続先の仕様と安全な保管方法を確認して実装する。

## 作業領域のサイズ調整

幅が1,024px以上の画面では、チャット・ターミナル側と文書プレビュー側の間に左右比率の調整ハンドルを表示する。チャットとターミナルの間には上下比率の調整ハンドルを表示する。ドラッグまたはハンドルにフォーカスして矢印キーで調整できる。

初期比率は左右50:50、チャットとターミナルは60:40。各比率は20〜80%の範囲に制限し、一方を完全に隠さない。比率は画面表示中だけ保持し、永続設定には保存しない。

狭い画面では縦並びを維持し、比率調整ハンドルは表示しない。ターミナルのサイズが変わった場合も、PTYへのリサイズは操作権を持つ画面だけが送る。

## フェーズごとのチャット

タスク内には各フェーズのチャットがあり、現在フェーズの会話を表示する。準備中はフェーズ名を選ぶと、その会話を再開する。文書タブの選択だけでは会話や現在フェーズを変更しない。文書は全フェーズで共有し、フェーズ切り替えでは内容を巻き戻さない。再開した会話への次の送信時に、未確認イベントの範囲をエージェントへ知らせ、埋め込みツールから参照させる。[変更履歴の仕様](../objects/task-events.md)
