# LLM向け埋め込みツール

LLMはプロジェクトイベントを調べ、必要に応じて差分やチャット出力を取得する。履歴は読み取り専用とし、イベントの作成や履歴の改変をLLMへ任せない。確認済み位置の更新だけは、専用の確認完了通知で受け付ける。

## ツール

| ツール | 主な入力 | 返す内容 |
| --- | --- | --- |
| list_events | after、through、limit、任意のtask_id・kind | イベントの要点、次のカーソル、続きの有無 |
| get_event | event_id | 実行内容・状態、ファイル変更、チャットへの参照 |
| get_file_change | event_id | 対象ファイルの差分・変更後ハッシュ |
| get_file_version | path、change_id | 指定した変更後の本文、ハッシュ、存在状態 |
| get_execution_output | operation_id | 参照先の現行・保管済みチャットに保存された出力の抜粋。参照先が削除されていれば削除済みと返す |
| acknowledge_events | through | 確認完了を受け付けた上限ID |

pathは対象版でのプロジェクト相対パスとし、change_idとの対応を検証する。復元の起点が全文キャッシュ・初版のどちらであっても、同じ版の本文を返す。

`list_events` の `limit` は1〜100（既定20）。タスク会話では、そのタスクのイベントを既定の対象とする。Generalはプロジェクト全体を対象とする。既定の一覧には、文書の変更、フェーズ遷移、タスク操作、実行結果の要点を返す。ツールの開始・終了を調べるときは `kind` に `tool.started` や `tool.finished` を指定する。個別イベントの詳細は `get_event` から取得する。イベントDBには出力本文を複製しない。

## スコープ

Beniが起動するエージェントには対象プロジェクトのスコープを与える。任意のパスや別プロジェクトのIDを入力して他のプロジェクトへアクセスできる設計にしない。同じプロジェクト内では他タスクのイベント・文書履歴・参照先チャット出力も取得できる。タスク指定は検索の絞り込みであり、別プロジェクトへの参照は許可しない。

Beniがエージェント実行時に提供する埋め込みツールとする。ツール定義・実行処理・プロジェクトおよび会話のスコープはBeniが管理する。Codexには動的ツールとして登録し、Claudeには Agent SDK のインプロセス MCP サーバーを通して提供する。ユーザーによる外部MCPサーバーの設定は不要。

## チャットへの引き継ぎ

送信時にプロジェクトのイベント末尾を固定する。判断に必要なイベントや差分だけを埋め込みツールで取得する。現在の文書と会話の引き継ぎで判断できる場合は一覧を走査しなくてよい。ページ取得中に増えたイベントは次の範囲とする。

LLM用の一覧では、対象タスクとイベント種類で絞り込んだ後にページを区切る。続きがある場合は同じ絞り込みで `nextCursor` から取得する。最終ページの `nextCursor` は送信時に固定した取得上限となる。

埋め込みツールの返却上限は1MiBとする。`get_execution_output` は出力末尾を優先して16KiB以内の抜粋を返し、取得時に短縮した場合は `omitted` を付ける。保存時に短縮した出力には、その時点の省略表示も含まれる。

確認済みカーソルは会話（General・タスクの各フェーズ）と接続先の組ごとに保持する。LLMから確認完了通知を受けた上限まで進める。取得範囲の通知や埋め込みツールでの取得では、確認済みカーソルを変更しない。

確認完了は、その会話に提示した範囲内の上限だけを受け付ける。上限までの確認を終えた通知として扱い、範囲外の値や他の会話のカーソル更新は拒否する。同じ通知の再送は重複として安全に扱い、カーソルを後退させない。確認完了通知なしで終了・切断した場合は次回も未確認範囲を知らせる。確認完了は、内容を理解したことや問題を解決したことの保証ではない。

`lastEventId` はLLMが確認完了を通知した上限を表す。送信受付時には自動更新しない。

タスク削除後もイベントと文書の過去版を取得できる。取得権限はプロジェクトのスコープで確認し、タスクやチャットが現存することをイベント参照の条件にしない。
