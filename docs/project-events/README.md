# プロジェクトイベント管理

プロジェクト内で「何をしたか」を記録し、LLMが埋め込みツールから必要な履歴を取得する。

- [保存形式とファイル差分](storage.md)
- [LLM向け埋め込みツール](tools.md)

## 合意した方針

- イベントはプロジェクト単位で管理し、SQLiteに保存する。
- ツール・コマンド実行、ファイル変更、フェーズ変更などを記録する。
- 実行出力はチャットに残す。イベントには重複保存せず、対応するチャットの実行への参照を持たせる。
- ファイル履歴は初版の全文と、その後の可逆な差分、変更後の本文ハッシュを保存する。
- 文書はプロジェクトからの相対パスで指定する。現在の一覧は移行済みの文書ではDB、移行前の文書ではファイルシステムから取得する。`files` テーブルや `file_id` は設けない。
- 過去の本文は初版や対象版以前の起点から、差分を順に適用して復元する。
- 全文キャッシュは10変更ごとに作り、古くなるほど保存間隔を倍にして間引く。初版と差分は残す。
- 本文の履歴はタスク文書とプロジェクトナレッジを対象とする。Gitの履歴とは独立して管理する。
- タスク削除後もイベントと復元に必要な文書履歴を残す。
- LLMからは埋め込みツールを通してイベントを参照できるようにする。

## イベントの対象

| 対象 | 記録する内容 |
| --- | --- |
| エージェントのツール・コマンド | Beniが通知を受け取った操作の種類、開始・終了、結果、参照先 |
| 文書 | 対象パス、作成・更新、本文差分と変更後ハッシュ。移行前のファイルは削除・改名も記録する |
| タスク | 作成、改名、フェーズ変更、完了、再開、削除 |
| ワークフロー | 開始・完了・失敗、ジョブID・試行ID・起点イベントと会話への参照 |

Generalのエージェント操作とプロジェクトナレッジはタスクに属さないイベントとして記録する。ターミナルへの手入力と出力はプロジェクトイベントの対象外とする。

## 内容を追跡する文書

- 固定文書：`requirements.md`、`documents.md`、`implementation.md`。
- 仕様整理で追加した資料・仕様のMarkdown文書。
- 反省会の文書：`retrospective.md`。
- プロジェクト共通のナレッジ文書：`knowledge.md`。

DB文書の変更は版と一緒にイベントへ記録する。ソースコード、リポジトリの `docs/` に配置した仕様のコピー、生成物は本文の追跡対象外とする。エージェントがこれらを操作したときも、イベントが持つのは観測できた実行情報とチャットへの参照までとする。

## チャットとの関係

チャットは会話と実行出力を保持し、イベントは操作と変更を横断して調べるために使う。

イベントから、タスク・フェーズ・会話ID・送信ID・ツール実行IDを辿れるようにする。実行IDは提供元のスコープ内でしか一意でない可能性があるため、単独では参照キーにしない。Generalの操作はタスク・フェーズを持たない。

イベントにはツール名・操作対象・結果・チャット参照を記録する。コマンド文字列や引数、標準出力・標準エラー・ツール応答本文はチャット側だけに残し、イベントへ重複保存しない。

## 記録のきっかけ

Beniが受け取るツールの開始・終了通知から実行情報を記録する。

1. 実行開始を記録する。
2. 実行終了を記録する。旧Markdownの移行前は、ここで実ファイルの変更も照合する。
3. DB文書は更新時に版、差分、ハッシュを保存する。イベントには文書の版を記録する。

失敗したコマンドにも途中までの変更があり得るため、移行前の照合は成功時に限らない。同じ実行の開始・終了は `operation_id` とイベント種別で重複を防ぐ。終了通知が得られなかった実行は成功と扱わない。

旧Markdownの手編集は、一覧やイベントの取得、イベントの購読開始などの照合時に検出する。常時のファイル監視による通知は未実装。記録済みハッシュとの比較で重複を防ぎ、変更と実行の対応を特定できる場合だけ関連づける。

旧Markdownについて記録できるのは照合時に観測した変更までとする。移行後の文書とナレッジはDBを正本とし、残したファイルの手編集を取り込まない。

## タスク削除後の履歴

タスク削除を一つのイベントとして記録し、イベント・文書の初版・差分をアプリデータ内のプロジェクト別DBに残す。タスク配下の一括削除を通常の文書編集による削除イベントとして大量に記録しない。削除直前までの文書変更を照合・保存してから削除し、最後に記録した版を含む過去の本文を復元可能にする。

チャット出力が削除されていれば、出力取得では削除済みである旨を返す。イベントが存在することと、参照先チャットが存在することは分けて扱う。

履歴を消せる明示的なオプションは将来追加する。今回は自動削除しない。全文キャッシュの間引きは継続できるが、復元に必要な初版・差分は残す。

## タスク完了時の処理

`task.completed` はタスクの完了という事実を記録する。このイベントに対応するアプリ共通インストラクションをバックグラウンドで実行する。ナレッジを上層へ反映する手順はインストラクション内に置く。[イベントに対応するワークフロー](../features/workflows.md)
