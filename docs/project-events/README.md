# プロジェクトイベント管理

プロジェクト内で「何をしたか」を記録し、LLMが埋め込みツールから必要な履歴を取得する。

- [保存形式とファイル差分](storage.md)
- [LLM向け埋め込みツール](tools.md)

## 合意した方針

- イベントはプロジェクト単位で管理し、SQLiteに保存する。
- ツール・コマンド実行、ファイル変更、フェーズ変更などを記録する。
- 実行出力はチャットに残す。イベントには重複保存せず、対応するチャットの実行への参照を持たせる。
- ファイル履歴は初版の全文と、その後の可逆な差分、変更後の本文ハッシュを保存する。
- ファイルは相対パスで指定する。現在の一覧はファイルシステムから取得し、filesテーブルやfile_idは設けない。
- 過去の本文は初版や対象版以前の起点から、差分を順に適用して復元する。
- 全文キャッシュは10変更ごとに作り、古くなるほど保存間隔を倍にして間引く。初版と差分は残す。
- 内容追跡はタスク文書に限定する。Gitとの連携は行わない。
- タスク削除後もイベントと復元に必要な文書履歴を残す。履歴削除のオプションは将来追加する。
- LLMからは埋め込みツールを通してイベントを参照できるようにする。

## イベントの対象

| 対象 | 記録する内容 |
| --- | --- |
| ツール・コマンド | 何を実行したか、開始・終了、成功・失敗・中断などの結果 |
| ファイル | 対象パス、作成・更新・削除、差分、変更後ハッシュ |
| タスク | フェーズ変更、完了、再開などの操作 |

タスクやフェーズに属さない操作も記録できるようにする。

## 内容を追跡する文書

- 固定文書：`requirements.md`、`documents.md`、`implementation.md`。
- 要件定義・仕様整理・実装手順で追加した資料・仕様のMarkdown。
- 反省会の文書：`retrospective.md`。

追跡対象になった文書は、実装中・反省会で編集された場合も継続して記録する。プロジェクト共通の `knowledge.md`、ソースコード、リポジトリの `docs/` に配置した仕様のコピー、生成物は内容追跡の対象外とする。これらを操作したツール・コマンドの実行自体は記録するが、本文や差分はイベントDBに保存しない。

## チャットとの関係

チャットは会話と実行出力を保持し、イベントは操作と変更を横断して調べるために使う。

イベントから、タスク・フェーズ・会話ID・送信ID・ツール実行IDを辿れるようにする。実行IDは提供元のスコープ内でしか一意でない可能性があるため、単独では参照キーにしない。Generalの操作はタスク・フェーズを持たない。

イベントにはツール名・操作対象・結果・チャット参照を記録する。コマンド文字列や引数、標準出力・標準エラー・ツール応答本文はチャット側だけに残し、イベントへ重複保存しない。

## 記録のきっかけ

Beniが受け取るツールの開始・終了通知を共通のイベント記録処理へつなぐ。LLMに記録用ツールの呼び出しを毎回任せる方式にはしない。

1. 実行開始を記録する。
2. 実行終了を記録し、実ファイルの変更を照合する。
3. 差分とハッシュを保存し、特定できる場合だけ原因となった実行へ紐づける。

失敗したコマンドにも途中までの変更があり得るため、成功時だけに照合を限定しない。通知の重複で同じ開始・終了を二重記録しない。終了通知が得られなかった実行は成功と扱わない。

ファイル監視と起動時・取得時の照合を併用する。手編集やコマンド経由の変更を拾い、記録済みハッシュとの比較で重複を防ぐ。並行実行中の変更は、時刻が近いことだけを理由に特定のツールへ帰属させない。

記録できるのは観測した変更。書き込みをすべてBeni経由に制限しない限り、連続書き込みの中間状態までは保証しない。

## タスク削除後の履歴

タスク削除を一つのイベントとして記録し、イベント・文書の初版・差分をプロジェクト側に残す。タスク配下の一括削除を通常の文書編集による削除イベントとして大量に記録しない。削除直前までの文書変更を照合・保存してから削除し、最後に記録した版を含む過去の本文を復元可能にする。

チャット出力が削除されていれば、出力取得では削除済みである旨を返す。イベントが存在することと、参照先チャットが存在することは分けて扱う。

履歴を消せる明示的なオプションは将来追加する。今回は自動削除しない。全文キャッシュの間引きは継続できるが、復元に必要な初版・差分は残す。
