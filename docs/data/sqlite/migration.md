# SQLiteの設計・移行

## 現行

保存先は `data/beni.sqlite`。`BENI_DATA_DIR` 指定時はその配下です。実装は `src/backend/store/index.ts` にあります。

| テーブル | 主な情報 |
| --- | --- |
| `projects` | `id`、`name`、`folder` |
| `tasks` | `id`、`project_id`、`name`、`phase`、`status` |
| `messages` | プロジェクト・タスク、発言者、本文、作成時刻を持つ旧形式 |
| `documents` | タスク、文書種別、版、本文、作成時刻を持つ旧形式 |

プロジェクトIDとタスクIDは、それぞれアプリDB内の連番です。タスクIDはプロジェクトごとの連番ではありません。会話ファイル名と文書ディレクトリもこのIDに依存しています。

`/api/state` のタスク一覧はDBから取得します。プロジェクトに文書が残っていても、DBにタスクがなければ一覧に出ません。

## 決定した移行方針

アプリ側は `projects` だけを残します。`tasks`・`messages`・`documents` のデータは対象プロジェクトの `.beni` へ移し、移行・照合後に旧テーブルを削除します。既存Markdownは旧DBの内容で上書きしません。旧文書履歴は正本への上書きと分けて引き継ぎ方法を決めます。

## 決めること

- 新しいIDと既存連番の対応、別DBからの取り込みでの衝突処理。
- 旧メッセージ・文書履歴の引き継ぎと廃止条件。

## 移行・検証

DBとファイルをまたぐ単一のトランザクションはありません。作成途中の失敗、移行再実行、欠落・重複参照を検証します。旧テーブルと旧データの削除は、移行先の内容・履歴・参照関係の照合が済んでから行います。

移行全体の順序と共通の検証は [全体の設計・移行](../migration.md) を参照します。
