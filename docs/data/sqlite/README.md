# SQLite

この文書はアプリDBを記載します。プロジェクト別DBもアプリデータ内に保存します。[保存先と移行](../storage.md)

保存仕様を定義します。

Beni自身に属するプロジェクトの登録情報・保存先への対応、アプリ共通のインストラクションの版と更新ジョブ、エージェントの連携情報を扱います。

## DB構成

アプリ側SQLiteの主なテーブルは次のとおりです。

```text
beni.sqlite
├── projects            プロジェクトID・名前・作成日時・更新日時・作業フォルダーの絶対パス
├── project_storage    移行状態・検証結果・旧データ削除の再開情報・作業先の世代
├── document_heads     指示キーと最新版の対応
├── document_versions  指示の版・順序付きの文書項目・根拠と参照
├── agents             エージェントの表示名・確認済みの接続情報・モデル一覧・利用枠
├── instruction_jobs   ワークフロー実行・イベント・指示とナレッジの版・接続先とモデル・状態と結果
├── chat_refs          用途・所有者・現行／アーカイブとチャットID
├── chat_changes       会話作成・切り替えの復旧情報
├── chat_deletions     会話削除の復旧情報
├── chat_migration_sources  移行元の指紋と移行状態
├── chat_migration_aliases  所有者ごとの旧IDと新IDの対応
└── instructions       版管理導入前のテンプレートの取り込み元
```

`projects.id` はTEXTで保存し、[共通ID規則](../README.md#idの共通規則)のプロジェクト用ID（第3グループ `7000`）を使います。`projects` がプロジェクト情報の正本です。名前や日時を含む旧 `project.json` をDBへ引き継いでから廃止します。プロジェクトDBの所属IDと登録ID・DBファイル名を照合し、取り違えを検出します。

`instruction_jobs` は保存互換のため旧テーブル名を維持する。現在は `task.completed` の実行を管理し、上層への反映方針はイベント用インストラクションの本文に置く。既存実行の結果と識別子は移行後も維持する。新規実行は `event_key`・`event_id`・`instruction_revision` を保存する。旧実行の `event_id` は未記録のままとし、指示の版には移行時の初期登録版を補う。この補完値を、過去の実行で使用された指示の証明として扱わない。

`agents` は登録IDを主キーとし、表示名と最後に確認した接続情報をエージェントごとに保存します。接続情報は利用可否、認証方式、モデル一覧、実行ファイルのパス、バージョン、確認日時、アカウント照合値です。モデル一覧と利用枠はJSONで保持します。認証トークン・APIキー・アカウントの生データは保存しません。実行の契約・対応コマンド・機能の有無は実装側の登録情報を正本とします。

通常の表示では保存済みの接続情報を使い、画面の再表示やサーバーの再起動だけではCLIに問い合わせません。初回、設定画面の「更新」、接続・認証・モデルの不一致などで保存値を無効化した後に再確認します。無効化では最後の確認内容と日時を残し、次の参照で再取得します。「確認日時」はCLIから接続情報を取得した時刻で、保存値の読出時刻ではありません。実行時の認証や権限の確認は各エージェントが引き続き行います。

利用枠には接続情報とは別のアカウント照合値と取得日時を持たせます。表示時は接続情報のアカウントと照合し、アカウントが切り替わった実行から利用枠を受け取った場合は接続情報を無効化して、以前のアカウントの利用枠を表示しません。同じアカウントの古い利用枠で上書きしません。接続の再確認だけでは利用枠の取得日時を更新せず、明示的な更新や会話中の利用枠イベントで更新します。

`projects.createdAt`・`projects.updatedAt` は旧JSONから引き継ぐ日時です。日時不明は `null` のまま保ち、`metadata_migrated` で未取り込みと区別します。プロジェクトDBの `project_identity` は所属IDを保持し、保存先の照合に使います。

`project_storage` はプロジェクトごとの移行確定と後片付けを管理します。作業フォルダー変更時に世代を進め、旧作業先に結び付いた会話の再開情報を無効化します。

インストラクションの正本は文書テーブルです。未移行のキーは旧 `instructions` のカスタマイズ済み本文を取り込み、本文が存在しない場合や既知の旧既定値と一致する場合は現行の既定値から初期化します。文書項目は文書版ごとにJSONで保持し、本文は項目の連結で生成します。

タスク情報・文書の正本は、アプリデータの `projects/<projectId>.sqlite` に置きます。プロジェクトDBの `tasks` に識別・状態・日時・文書比較基準・完了処理の復旧情報を保存します。[タスクの保存と移行](../task-management.md)会話の正本は `chats/<chatId>.json` に置き、用途・所有者とチャットIDの参照をアプリDBで管理します。アプリ側にタスクの検索索引は置きません。アプリDBに旧試作の `tasks`・`messages`・`documents` テーブル、またはTEXT型以外の `projects.id` がある場合は起動時に拒否します。プロジェクト内の旧Markdownの取り込みは [プロジェクトデータ](../beni/README.md) を参照してください。

プロジェクト・タスク・会話・文書の参照は、保存先の変更や再登録でも混同しないように設計します。移動・再登録ではプロジェクトIDを維持します。

## チャット参照

アプリDBは用途・所有者ごとの現行チャットとアーカイブを管理します。Generalはプロジェクト、タスク会話はタスクとフェーズ、ワークフロー会話は実行、編集相談はアプリ共通の参照を持ちます。旧IDから新IDへの対応と、JSONとDBをまたぐ操作の復旧情報も保持します。詳細は [チャット管理](../chat-management.md) に従います。
