# SQLite

保存仕様を定義します。

Beni自身に属するプロジェクトの登録情報・保存先への対応、アプリ共通のインストラクションの版と更新ジョブを扱います。

## DB構成

アプリ側SQLiteの主なテーブルは次のとおりです。

```text
beni.sqlite
├── projects            プロジェクトID・表示名のコピー・保存先の絶対パス
├── document_heads     指示キーと最新版の対応
├── document_versions  指示の版・順序付きの文書項目・根拠と参照
├── instruction_jobs   更新依頼・入力のナレッジ版・接続先とモデル・状態と結果
└── instructions       版管理導入前のテンプレートの取り込み元
```

`projects.id` はTEXTで保存し、[共通ID規則](../README.md#idの共通規則)のプロジェクト用ID（第3グループ `7000`）を使います。`.beni/project.json` の `id` を正本とし、同じ値を登録します。名前の正本も `project.json` とし、`projects.name` は一覧表示用のコピーとして同期します。

インストラクションの正本は文書テーブルです。未移行のキーは旧 `instructions` のカスタマイズ済み本文を取り込み、本文が存在しない場合や既知の旧既定値と一致する場合は現行の既定値から初期化します。文書項目は文書版ごとにJSONで保持し、本文は項目の連結で生成します。

タスク情報・文書・会話の正本は、対象プロジェクト直下の `.beni` に置きます。アプリ側にタスクの検索索引は置きません。アプリDBに旧試作の `tasks`・`messages`・`documents` テーブル、またはTEXT型以外の `projects.id` がある場合は起動時に拒否します。プロジェクト内の旧Markdownの取り込みは [プロジェクトの .beni](../beni/README.md) を参照してください。

プロジェクト・タスク・会話・文書の参照は、保存先の変更や再登録でも混同しないように設計します。移動・再登録ではプロジェクトIDを維持します。
