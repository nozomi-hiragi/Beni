# SQLite

実装後も残す仕様のたたき台です。現行形式と未決事項は [設計・移行](migration.md) に分けます。

Beni 自身に属するプロジェクトの登録情報と、プロジェクトの保存先への対応を扱います。

## DB構成

アプリ側SQLiteのテーブルは `projects` だけとします。全体設定用テーブルやタスクの検索索引は今回追加しません。

```text
beni.sqlite
└── projects
    ├── id       プロジェクトの識別子
    ├── name     project.jsonの表示名のコピー
    └── folder   プロジェクトの保存先
```

`id` はTEXTで保存し、[共通ID規則](../README.md#idの共通規則)のプロジェクト用ID（第3グループ `7000`）を使います。`.beni/project.json` の `id` を正本とし、同じ値を登録します。JSONカラムは追加しません。名前の正本も `project.json` とし、`projects.name` は一覧表示用のコピーとして同期します。

タスク情報・文書・会話の正本は、対象プロジェクト直下の `.beni` に置きます。アプリ側に `tasks`・`messages`・`documents` テーブルは持ちません。移行後の形式は [プロジェクトの .beni](../beni/README.md) で定義します。

プロジェクト・タスク・会話・文書の参照は、保存先の変更や再登録でも混同しないように設計します。移動・再登録ではプロジェクトIDを維持します。別プロジェクトとして複製する場合は新しいプロジェクトIDを発行します。
