# プロジェクトの .beni

保存仕様を定義します。

プロジェクト内で完結するデータはプロジェクト側に配置します。タスクの要件・実装計画などの文書は `.beni` 内の実ファイルを正本にします。表示用HTMLは派生データです。

タスクの識別情報・名前・フェーズ・状態、文書、ジェネラル・タスク会話を `.beni` にまとめます。プロジェクトを移動すると、これらのデータも一緒に移動する構成とします。

## ディレクトリ構成

```text
.beni/
├── project.json                  プロジェクト情報
├── events.sqlite                 プロジェクトイベント・文書差分・全文キャッシュ
├── knowledge.md                  プロジェクト共通のナレッジ（必要時）
├── chat/
│   ├── general.json              ジェネラル会話
│   └── <taskId>/
│       └── <phase>.json          フェーズ別のタスク会話
└── tasks/
    └── <taskId>/
        ├── task.json             タスク情報
        ├── requirements.md       要件定義
        ├── documents.md          仕様整理（資料・仕様の目次）
        ├── implementation.md 実装手順
        ├── retrospective.md      反省会の記録（反省会から）
        └── *.md                  追加文書（資料または仕様）
```

メタデータと会話はJSON、文書本文はMarkdownの実ファイルに保存します。イベント・文書履歴はプロジェクト側の `events.sqlite` に保存します。会話はタスクフォルダーへ置かず、`chat/` にまとめます。

会話の保存内容・更新規則は [chat/ の仕様](chat.md) を参照します。

## タスクID

タスクIDは [共通ID規則](../README.md#idの共通規則)に従うUUIDv7ベースのID（第3グループ `7100`）とし、`task.json` のID、タスクフォルダー名、chat配下のタスクフォルダー名に同じ値を使います。プロジェクトIDを連結した別のタスクUIDは作りません。

UUIDv7は生成時刻を含むため、IDによって時刻順に並べやすい形式です。ただし複数環境の時計や同時生成を含む厳密な操作順序の保証には使いません。作成日時は `createdAt` にも記録します。日時はUTCのISO 8601形式で記録します。

タスク一覧は `tasks/*/task.json` を読み取って構成します。プロジェクトIDは同じ共通規則のプロジェクト用ID（第3グループ `7000`）とし、`project.json` の `id` に保存します。移動・再登録ではIDを維持します。

文書が残っていることだけで、タスク名・フェーズ・実行結果を推測して確定しません。登録が欠けても残存ファイルを上書き・削除しません。

プロジェクト内に置くことと、Gitに含めることは別です。実ユーザーデータを公開リポジトリへ自動追加しません。

## メタデータ

`version` はJSONの保存形式を示す整数で、初版は `1` とします。更新回数ではありません。新規作成時の `createdAt`・`updatedAt` はUTCのISO 8601形式（末尾 `Z`）で保存します。復元時に過去日時を確認できない場合は `null` を保存し、IDの生成時刻を過去の作成日時として代用しません。以下は架空のデータです。

### project.json

```json
{
  "version": 1,
  "id": "019a5000-0000-7000-8000-000000000001",
  "name": "サンプルプロジェクト",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

プロジェクト名はこの `name` が正本です。SQLiteの名前は一覧表示用のコピーとして同期します。絶対パスは `project.json` に保存せず、アプリ側の登録情報に持たせます。

### task.json

```json
{
  "version": 1,
  "id": "019a5000-0000-7100-8000-000000000002",
  "name": "サンプルタスク",
  "phase": "requirements",
  "status": "idle",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

タスクには共通項目に加え `phase`・`status` を持たせます。例は初期状態です。状態の値・遷移はワークフロー仕様と合わせ、保存形式だけを理由に増やしません。所属プロジェクトは `.beni` の配置から決まり、タスクIDにプロジェクトIDを連結しません。

### タスクの更新日時

`updatedAt` は、タスク名・会話・文書のうち最後に更新された日時です。タスク会話では発言・応答・ツール結果などを保存したとき、文書では対象の Markdown の追加・本文変更・削除を検出したときに更新します。ジェネラル会話はプロジェクトに属するため、タスクの更新日時には反映しません。

開いているタスクの文書は変更通知で確認します。閉じている間の変更も、次にタスク一覧や詳細を読み込んだときに照合します。既存文書を最初に照合するときは比較の基準だけを記録し、以前の更新日時を保ちます。`task.json` の `documentBaseline` に各文書のファイル名、本文のSHA-256、ファイル更新時刻（ミリ秒）を記録します。文書の変更時刻が分かる場合はその時刻を、削除など変更時刻を特定できない場合は検出時刻を使います。画面の再読み込みや、本文が同じファイルの再保存でタスクの順番は変わりません。

## 移動・復元

移動・再登録・バックアップ復元ではプロジェクトIDとタスクIDを維持します。

複数起動の扱いは [Beni全体の動作条件](../../next-agent-plan.md#動作条件) に従います。

## 文書だけ残ったタスク

`task.json` がなく文書が残ったフォルダーは、名前を `Unknown` として自動登録・復元します。ユーザーの確認や名前入力を待ちません。元の文書は維持し、本文からタスク名を推測しません。復元済みのタスクを再検出しても重複登録しません。過去のフェーズ・状態・日時を文書から推測して埋めません。復元後の操作を始める初期値は `phase: requirements`・`status: idle` とし、過去の状態を復元できたとは扱いません。不明な過去日時は `null` とします。

## 反省会と完了状態

反省会のphaseは `retrospective`。初回到達時にタスクフォルダの `retrospective.md` を用意し、既存本文は上書きしない。通常のタスク文書として変更履歴を保存する。タスクの完了は `status: completed`、再開後は `status: idle` とし、phaseは反省会のまま維持する。完了・再開で更新日時を更新する。

プロジェクト共通の `.beni/knowledge.md` は反省会で蓄積し、次のタスクに引き継ぐ。タスクの文書変更イベントには含めず、送信時に最新版を参照する。
