# プロジェクトの .beni

実装後も残す仕様のたたき台です。現行形式と未決事項は [設計・移行](migration.md) に分けます。

プロジェクト内で完結するデータはプロジェクト側に配置します。タスクの要件・実装計画などの文書は `.beni` 内の実ファイルを正本にします。表示用HTMLは派生データです。

タスクの識別情報・名前・フェーズ・状態、文書、ジェネラル・タスク会話を `.beni` にまとめます。プロジェクトを移動すると、これらのデータも一緒に移動する構成とします。

## ディレクトリ構成

```text
.beni/
├── project.json                  プロジェクト情報
├── chat/
│   ├── general.json              ジェネラル会話
│   └── <taskId>.json             タスク会話
└── tasks/
    └── <taskId>/
        ├── task.json             タスク情報
        ├── requirements.md       要件
        └── implementation-plan.md 実装計画
```

メタデータと会話はJSON、文書本文はMarkdownの実ファイルに保存します。プロジェクト専用SQLiteは追加しません。会話はタスクフォルダーへ置かず、`chat/` にまとめます。

会話の保存内容・更新規則は [chat/ の仕様](chat.md) を参照します。

## タスクID

タスクIDは [共通ID規則](../README.md#idの共通規則)に従うUUIDv7ベースのID（第3グループ `7100`）とし、`task.json` のID、タスクフォルダー名、会話JSONのファイル名に同じ値を使います。プロジェクトIDを連結した別のタスクUIDは作りません。

UUIDv7は生成時刻を含むため、IDによって時刻順に並べやすい形式です。ただし複数環境の時計や同時生成を含む厳密な操作順序の保証には使いません。作成日時は `createdAt` にも記録します。日時はUTCのISO 8601形式で記録します。

タスク一覧は `tasks/*/task.json` を読み取って構成します。プロジェクトIDは同じ共通規則のプロジェクト用ID（第3グループ `7000`）とし、`project.json` の `id` に保存します。移動・再登録では維持し、別プロジェクトとしての複製では新しく発行します。別プロジェクトとして複製する場合はタスクIDも再発行します。

文書が残っていることだけで、タスク名・フェーズ・実行結果を推測して確定しません。登録が欠けても残存ファイルを上書き・削除しません。

プロジェクト内に置くことと、Gitに含めることは別です。実ユーザーデータを公開リポジトリへ自動追加しません。

## メタデータ

`version` はJSONの保存形式を示す整数で、初版は `1` とします。更新回数ではありません。`createdAt`・`updatedAt` はUTCのISO 8601形式（末尾 `Z`）で保存します。以下は架空のデータです。

### project.json

```json
{
  "version": 1,
  "id": "019a5000-0000-7000-8000-000000000001",
  "name": "サンプルプロジェクト",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

プロジェクト名はこの `name` が正本です。SQLiteの名前は一覧表示用のコピーとして同期します。絶対パスは `project.json` に保存せず、アプリ側の登録情報に持たせます。

### task.json

```json
{
  "version": 1,
  "id": "019a5000-0000-7100-8000-000000000002",
  "name": "サンプルタスク",
  "phase": "requirements",
  "status": "idle",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

タスクには共通項目に加え `phase`・`status` を持たせます。例は初期状態です。状態の値・遷移はワークフロー仕様と合わせ、保存形式だけを理由に増やしません。所属プロジェクトは `.beni` の配置から決まり、タスクIDにプロジェクトIDを連結しません。

## 移動・復元・複製

移動・再登録・バックアップ復元ではプロジェクトIDとタスクIDを維持します。別プロジェクトとして複製するときは、プロジェクトと全タスクのIDを再発行し、ディレクトリ名・会話ファイル名・構造化データ内の参照を新IDへ揃えます。自由文を機械的に置換しません。複製元は変更しません。

複数起動の扱いは [Beni全体の動作条件](../../next-agent-plan.md#動作条件) に従います。

## 文書だけ残ったタスク

`task.json` がなく文書が残ったフォルダーは、名前を `Unknown` として自動登録・復元します。ユーザーの確認や名前入力を待ちません。元の文書は維持し、本文からタスク名を推測しません。復元済みのタスクを再検出しても重複登録しません。過去のフェーズ・状態・日時を文書から推測して埋めません。登録時に採用する状態と不明な日時の表現は移行仕様で決めます。
