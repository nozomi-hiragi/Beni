# プロジェクトの .beniの設計・移行

## 移行元の文書形式

`src/backend/documents.ts` が `<project>/.beni/tasks/<taskId>/` を管理します。

```text
<project>/.beni/
└── tasks/
    └── <taskId>/
        ├── requirements.md
        └── implementation-plan.md
```

対象の英字名Markdownも読み取ります。文書の表示・送信時に、存在しない文書を旧DBの内容などから初期化します。既存ファイルは上書きしません。`BENI_DATA_DIR` はこの保存先に影響しません。

ディレクトリ名はアプリDBのタスクIDです。フォルダーの走査による未登録タスクの取り込みはありません。既存ディレクトリと衝突する新規タスク作成は拒否します。

## 決定した移行方針

旧DBのタスク情報・メッセージ・文書履歴と、アプリ側の会話JSONを `.beni` へ移します。すでにある文書は保持し、旧DBの内容で上書きしません。文書だけ残ったタスクは `Unknown` という名前で自動登録・復元します。ユーザーの確認・名前入力は不要です。

既存の整数タスクIDには [共通ID規則](../README.md#idの共通規則) のIDを割り当てます。旧IDと新IDの対応を保存し、文書ディレクトリ、会話ファイル、JSON内のタスク参照を揃えて移行します。移行の再実行で別のUUIDを割り当てないようにします。既存タスクの過去日時が不明な場合は `null` とし、IDの生成時刻から推測しません。

## 移行後の扱い

- メタデータの初版は `version: 1`。非対応バージョンや不正な項目は上書きせず拒否します。
- 自動復元は `Unknown`・`requirements`・`idle` から開始します。既存文書は維持し、過去状態を推測しません。
- 旧DBのメッセージ・文書の全履歴は `.beni/legacy-history.json` に保存します。旧IDと新タスクIDの対応も記録します。
- 旧メッセージには送信・パックの確定状態や接続先情報がないため、実行履歴を推測して会話JSONへ変換しません。旧DBだけにあった履歴はこのJSONを直接開いて参照します。チャット画面には自動合成しません。
- バックアップと再実行の手順は [移行手順](../migration.md) に従います。

## 移行・検証

文書だけ残ったタスクが入力待ちにならず `Unknown` で復元され、再実行でもタスクやIDが増えず、元の文書が変わらないことを確認します。

文書だけ、登録だけ、会話だけが残った状態を区別します。不明な項目は不明のまま扱い、原文を保持して復元します。別DBの同じ番号を同一タスクとして誤って結び付けないことを検証します。

移行全体の順序と共通の検証は [全体の設計・移行](../migration.md) を参照します。

## 会話の移行

### 移行元の会話保存

`src/backend/chat.ts` が次のファイルを読み書きします。

| 保存先 | 会話 |
| --- | --- |
| `data/chat/<projectId>-<taskId>.json` | タスク会話 |
| `data/chat/<projectId>-general.json` | ジェネラル会話 |

`BENI_DATA_DIR` 指定時は、その配下の `chat/` を使います。会話JSONは文書と別の場所にあるため、プロジェクトフォルダーだけを移動しても会話は付いてきません。

### 会話の移行方針

アプリ側の `data/chat/` にあるジェネラル・タスク会話を、対象プロジェクトの `.beni` に移します。移行先はジェネラルが `chat/general.json`、タスク会話が `chat/<UUIDv7>.json` です。旧タスクIDとUUIDv7の対応を使い、ファイル名と会話内の参照を合わせます。パックIDや送信IDはタスクIDとは別であり、タスクID変更だけを理由に再発行しません。移行・照合が完了するまで元ファイルは削除しません。

### 会話の変換

会話の形式バージョン・メッセージ・パックと、ファイル名に対応するプロジェクト・タスクの参照を検証します。会話JSON内のプロジェクト・タスク参照を新IDへ更新し、それ以外の履歴を保持します。変換できない履歴は成功扱いにせず停止します。

CLI側で会話を再開できなくても、保存済みの履歴は残します。別プロジェクトへの複製ではCLI側セッションを引き継がず、新しい実行を元会話へ接続しません。

### 会話の検証

本文だけでなく、パックID・順序・確定内容・送信状態・接続先識別子を照合します。生成途中と結果不明を成功として取り込まず、移行を契機とした自動再送を行いません。



## フェーズ別会話への移行

旧 `chat/<taskId>.json` は最初の会話読み込み時に `chat/<taskId>/requirements.json` へ引き継ぐ。元の発言・パック・会話ID・CLIセッションを保持し、phaseをrequirements、イベントカーソルを0にする。他のフェーズへ複製しない。

移行先を安全に保存してから旧ファイルを取り除く。中断後に両方が存在する場合、同じ移行内容なら処理を再開できる。異なる履歴が存在する場合は上書きせずエラーとする。既存文書の最初の版は導入時の内容を記録し、それ以前の履歴を生成しない。
