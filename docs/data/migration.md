# データの移行と複製

旧形式のデータを、アプリ側SQLiteの登録情報とプロジェクト側の `.beni` に分けます。保存後の仕様は [データ設計](README.md)、旧テーブルの詳細は [SQLiteの移行](sqlite/migration.md)、文書・会話の引き継ぎは [.beniの移行](beni/migration.md) を参照してください。

## 移行の実行

Beniを停止し、対象プロジェクトの文書も編集されていない状態で実行します。サーバー起動時は旧DBを検出すると移行を案内して停止し、自動変換しません。

```sh
# Beniのリポジトリで実行。引数は旧beni.sqliteとchat/があるフォルダー
bun run migrate:data -- /path/to/beni-data
```

`BENI_DATA_DIR` を指定していた場合も、移行コマンドにはその保存先を明示します。プロジェクトフォルダーが移動済み・存在しない場合は、移行前に旧登録情報と対応を合わせます。

移行では次を行います。

1. 旧DBの参照関係を検査し、プロジェクト・タスクの新ID対応表を保存する。
2. SQLiteの整合したバックアップ、旧会話、各プロジェクトの `.beni` を保存する。
3. メタデータ・文書・会話・旧履歴をプロジェクト側へコピーし、内容を照合する。
4. 照合できた旧データを廃止し、アプリDBを `projects` だけの構成へ切り替える。

バックアップとID対応表は `<data-directory>/migrations/v1/` に残します。移行後の起動確認が済むまで削除しないでください。既存のMarkdownは旧DBの本文で上書きしません。パックID・本文・順序を維持し、生成途中の要求を移行処理が再送することはありません。

## 中断・エラー

移行が中断したら、元のBeniを起動せず同じコマンドを再実行します。保存済みID対応表を使い、二重登録や別IDの発行を避けます。生成済みファイルの改変、別データとの衝突、不正な参照、未対応の形式がある場合は上書きせず停止します。

エラーが出た場合は、バックアップ・対応表・移行途中のファイルを保全して原因を確認します。対応表だけを消して最初からやり直すと、参照が崩れるため行いません。登録に対応しない会話ファイルなど、移行できたと確認できないファイルは削除せず残します。

手動で移行前へ戻す場合はBeniを止め、SQLite・会話・プロジェクトごとの `.beni` を同じバックアップ時点に揃えて復元します。復元先の移行途中データは別の場所へ退避してから置き換えます。SQLiteだけを戻しても文書やIDの整合性は戻りません。自動ロールバック機能は提供しません。

旧数値IDのURLは新しいIDへリダイレクトしません。移行後はホーム画面からプロジェクト・タスクを開き直します。

## 別プロジェクトとしてデータを複製する

```sh
bun run clone:project -- /path/to/source-project /path/to/destination-project
```

このコマンドは `.beni` のデータを複製します。ソースコードなど、プロジェクトのその他のファイルはコピーしません。宛先に既存の `.beni` がある場合は拒否します。同じ宛先内の一時ディレクトリで検証・変換し、完成してから `.beni` として配置します。処理が失敗した場合はその一時ディレクトリだけを削除し、既存の宛先ファイルと複製元を変更しません。

プロジェクト・タスクのIDを再発行し、フォルダー名・会話ファイル名・構造化参照を更新します。文書本文は保持します。接続先の会話セッションは共有せず、複製した会話の未完了状態は結果不明として扱い、自動実行しません。複製後は宛先をBeniに登録してください。

移動・再登録・バックアップ復元では複製コマンドを使わず、元のIDを維持します。

## 検証

架空のデータで、正本と参照関係、文書の保持、会話パックの維持、Unknownの自動復元、再実行、衝突・不正データの拒否を確認します。複数起動は [Beni全体の動作条件](../next-agent-plan.md#動作条件) により動作保証外です。
