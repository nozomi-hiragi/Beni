## HTTP と WebSocket の役割

通常の要求と応答には HTTP を使い、リアルタイム通信には共通の WebSocket を使います。機能を追加・削除するときに、接続管理まで作り直さずに済む構成にします。

| 対象 | HTTP | WebSocket |
| --- | --- | --- |
| プロジェクト・タスク | 一覧・詳細取得、作成・変更 | 必要な更新通知 |
| フォルダー・設定 | 一覧取得、状態取得・変更 | 必要になった通知 |
| チャット | 履歴取得、送信、中断、パックの照合・補完 | 返答の差分、パック終了通知 |
| 文書・プレビュー | 内容取得 | ファイル更新通知 |
| ターミナル | 管理操作の API は別途定義 | 入出力、リサイズ、終了通知 |

HTML・JavaScript・CSS も HTTP で配信します。バックエンドと Codex など外部サービスの通信は、この仕様とは別です。

## 仕様の分担

接続・購読・イベント形式・再接続の手順は [WS メッセージ](websocket.md)、パックの確定と欠落の補完は [チャット同期](chat-sync.md) に定義します。HTTP の入口と入出力は [HTTP API](http-api.md) を参照してください。

共通の型とメッセージ定義は `src/shared/` に置きます。受信データは実行時にも検証します。

作成や送信などの操作は自動再送しません。応答を受け取れなかった場合、サーバー側で実行済みの可能性があります。結果不明を成功扱いせず、タイムアウトも処理の取り消しとは扱いません。

## ターミナルを追加するとき

ターミナルの入力・出力・リサイズ・終了通知は共通 WebSocket を使います。作成・終了などの管理操作の具体的な API は、ターミナル実装時に定めます。

- プロジェクト内のターミナルタブとシェルを一対一で対応させます。
- タブの明示的な終了操作でシェルを終了します。
- 画面の切り替えや通信の切断は、シェルの終了とは分けます。
- 再接続時は同じシェルへ接続し直します。サーバー再起動をまたぐ維持は対象外です。
- プロジェクトのステータス表示や、外部からシェル状態を確認する API は後の作業です。

ターミナル出力は文書の変更通知と違い、内容を捨ててまとめられません。出力量の制限、遅い受信側への対応、再接続時の表示復元は、ターミナル実装時に決めます。無制限に出力をためたり、他の操作を妨げたりしない設計が必要です。

## 境界で確認すること

接続先はローカルの Beni サーバーとします。WebSocket の接続時も Host と Origin を確認し、許可した同一オリジンからだけ受け付けます。Tailscale 経由の公開や認証は、この仕様の対象外です。

接続できたことだけを根拠に処理せず、操作・購読ごとに入力とプロジェクト・タスクの対応関係を確認します。不明な操作や不正なメッセージは明示的なエラーにします。

受信サイズ、未完了の要求数、購読数、送信待ちデータ量には上限を設けます。上限値は用途ごとに定め、操作の入力と文書を含む応答を区別します。エラーへ秘密情報や内部の例外をそのまま載せません。
