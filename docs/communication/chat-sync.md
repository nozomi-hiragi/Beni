# チャットのパック同期

[HTTP API](http-api.md) と [WS メッセージ](websocket.md) が通信形式を定義し、この文書は状態と同期手順を定義します。

## チャットのパック

パックは、チャットバブルに相当する返信の区切りです。返信全体ではなく、パック単位で内容を照合・確定します。ツール呼び出しが挟まる場合、その直前の説明を一つのパックとして閉じます。たとえば「説明 → ツール呼び出し → 結果の説明」では、最初の説明の同期を返信全体の終了まで待ちません。

パックには会話内の順序と ID があり、WS の差分・終了通知と HTTP の同期は同じパック ID を参照します。生成中の内容は FE で未確定として表示し、BE と同期できた内容を確定データとして記録・保持します。

パックは順番に確定します。FE が持つ「最新の確定済みパック ID」までは、すべてのパックが欠落なく確定している状態です。後続パックの差分は、前のパックの同期中でも未確定として受信・表示できます。

### 通常の受信と確定

1. FE が HTTP でメッセージを送信する。受け付けの成功と返答の完了は区別する。
2. BE がパック ID 付きの差分を WS で送り、FE は未確定データとして保持・表示する。
3. パックの区切りで BE が内容を確定・保存し、WS でパック終了を通知する。
4. FE が手元の未確定パックからハッシュを計算し、パック ID とハッシュを受け取り完了通知として HTTP で送る。
5. BE が保存済みの内容と照合する。一致なら OK、不一致なら正しいパック全文を HTTP の応答で返す。
6. FE は一致した内容、または BE から受け取った正しい全文を確定データとして記録し、未確定から外す。

ハッシュの単位はパックです。表示用 HTML ではなく、双方で同じ規則によって表現したパックのデータを使います。

BE のパック終了・保存は FE の確認を待ちません。FE の確定は、保存された内容との同期が完了したことを意味します。終了済みパックは照合中に内容が変わらないものとして扱います。

### 再接続時の同期

生成途中で切断した場合、再接続後に BE が送る差分から表示を再開します。パック冒頭が欠けていても構いません。過去の差分の再送や、再開位置の管理は行いません。パック終了時にハッシュを照合すれば、欠落は不一致となり、正しい全文で補完できます。

終了通知自体を逃したパックや、丸ごと未取得のパックは、パック ID 列を使って同期します。

1. WS の購読を復元する。
2. FE が最新の確定済みパック ID を HTTP で送る。まだ確定済みパックがなければ、先頭から同期する。
3. BE がその ID より後のパック ID 列を順序付きで返す。各パックが生成中か終了済みかも含める。
4. FE は終了済みで未確定・未取得のパックを HTTP で取得し、順番に確定データとして保持する。
5. 生成中のパックは WS の差分から表示し、終了通知を受けたら通常のハッシュ照合で確定する。

同期中の WS 通知と HTTP の結果はパック ID で突き合わせます。すでに確定したパックへ遅れて届いた差分を追記したり、同じパックを二重に記録したりしません。同期中に終了したパックも終了通知から照合へ進めます。
