# Navbar のツール

Navbar から使う手動ツールの仕様。

Navbar の右側の操作群に「ツール」ボタンを追加する。表示中の画面に対応したツールを一覧から選び、引数を入力して直接実行できるようにする。Beni が指定されたツールを実行し、専用ダイアログに結果を表示する。実行内容と結果はチャット履歴へ追加しない。

ツールの作業範囲は [プロジェクトイベントの埋め込みツール](../project-events/tools.md) と [文書管理](../traceable-documents-design.md) に従う。この文書では Navbar からの手動操作と、その実行に必要な差分を定義する。

## 対象と操作範囲

初回は Beni が定義・引数スキーマ・実行処理を管理する埋め込みツールを対象とする。プロジェクト・タスク・現在のフェーズと状態に応じて利用でき、手動実行の条件を満たすものを「有効なツール」とする。チャットの選択モデル、接続先、CLI の接続状態には依存させない。モデル未選択でも利用できる。

CLI 内部の Read・Bash・シェル実行などは対象外とする。現在の Agent インターフェースには、それらの一覧・引数スキーマ・直接実行の共通 API がないためである。外部 MCP の接続・ツールの追加・有効化設定も今回には含めない。

操作対象は表示中の画面から決め、ダイアログの上部に対象名を明示する。

| 表示中の画面 | 操作対象 |
| --- | --- |
| プロジェクト画面でタスク未選択 | そのプロジェクト |
| プロジェクト画面でタスクを選択 | そのプロジェクト・タスク・現在のフェーズ |
| インストラクション管理 | 共通のインストラクション。必要な編集対象はツールの引数で指定 |
| ホーム・設定など対象のない画面 | 対象なし。以前の画面のプロジェクトやタスクを引き継がない |

チャット入力欄の有無でボタンを表示・非表示にしない。実装中・終了・完了済みのタスクも、既存の制限に従って参照可能なツールを利用できる。手動の更新は、要件定義・仕様整理・実装手順・入力可能な反省会、およびインストラクション管理の既存の編集範囲に限る。過去フェーズのチャットを閲覧しても操作対象のフェーズは切り替えず、実際の現在フェーズを表示する。

## 配置とダイアログ

Navbar 右側の操作群で、既存のインストラクション管理ボタンの左にツールボタンを置く。チャット下部のコマンドボタンはそのままとする。

```text
[ホーム] タイトル              利用状況  [ツール] [インストラクション] [設定]
```

- Navbar の既存ボタンに合わせたアイコンボタンとし、ツールチップとアクセシブルな名前を「ツール」にする。
- ボタンから専用ダイアログを開き、ツールの一覧・引数入力・結果確認をその中で完結させる。画面に収まる高さと幅へ制限し、長い一覧や結果は内部をスクロールする。
- 一覧は「イベント・履歴」「文書」「インストラクション」に分類し、既存のコマンドメニューと同じ折りたたみ表示にする。空の分類は出さない。
- 各項目には実際のツール名と短い説明を表示する。長い名前・説明は折り返す。
- ボタン・項目は Tab で移動し、Enter・Space で開閉・選択できる。ダイアログを開いたら内部へフォーカスを移し、操作中のフォーカスを内部に保つ。閉じたら Navbar のツールボタンへ戻す。
- 実行前は「閉じる」または Escape で閉じられる。背景のクリックでは閉じず、引数入力を誤って失わないようにする。
- プロジェクト・タスク・画面の切り替えやフェーズ変更では、古い対象の引数を新しい対象へ流用しない。実行前ならダイアログを閉じ、次に開いたときに対象と一覧を取得し直す。
- 受付済みの操作は開始時の対象に結び付けたままにする。画面が変わっても対象を差し替えず、結果確認時には元の対象名を明示する。モデルの切り替えや会話リセットは操作対象を変更しない。

一覧の読み込み中・取得失敗・空の一覧を区別する。失敗時はダイアログ内に再取得操作を出す。有効なツールがない場合は「この画面で使えるツールはありません」、操作対象がない場合は「プロジェクトまたはインストラクション管理を開いてください」と表示する。取得失敗を空の一覧として扱わない。

対象の読み込みに失敗した場合や、同じ対象で通常送信・コマンド・ツール・自動処理が実行中の場合は、直接実行を受け付けず理由をダイアログに表示する。他のプロジェクトなど競合しない対象の操作は妨げない。作業フォルダーや保存データが利用できない場合も、新規の手動実行は受け付けない。CLI の起動や認証を必要としない。

## 引数の入力

項目を選ぶと同じダイアログ内の引数入力へ進み、対象名・ツール名・説明・引数・「実行」「一覧へ戻る」を表示する。項目の選択だけでは実行しない。引数がないツールも「実行」で確定する。

入力欄はバックエンドが返す引数スキーマから作る。

| 引数の型 | 入力方法 |
| --- | --- |
| 文字列 | テキスト入力。本文など長い値は複数行入力 |
| 数値・整数 | 数値入力。整数・上下限を検証 |
| 真偽値 | オン・オフの入力 |
| 列挙値 | 選択欄 |
| オブジェクト・配列 | 型と説明を添えた JSON 入力 |

必須項目を示し、省略・空文字・`null`・`false`・`0` を区別する。任意項目には「指定する」状態を持たせ、未指定の項目は送信するオブジェクトに含めない。既定値がある場合は説明へ表示する。`null` はスキーマが許す場合だけ選べるようにする。

初回のフォーム生成は既存ツールのスキーマで必要な型と制約に絞る。フォームで表せない構造には JSON 入力を使い、入力値を勝手に削除・変換しない。必須項目、型、列挙値、数値範囲、配列件数、追加プロパティの可否などを検証する。最終的な検証はバックエンドで必ず行う。

入力エラーは対象項目の近くに表示し、入力を保持する。実行中は二重送信を防ぐ。「一覧へ戻る」は引数入力からツール一覧へ戻る操作とする。「閉じる」と Escape はダイアログを閉じる操作であり、実行済みの変更を取り消すものとはしない。

ツールの操作によってチャットの下書きを変更しない。

## 有効なツールの決め方

バックエンドを一覧の情報源とする。エージェントへ渡す埋め込みツールと手動実行で、名前・説明・引数スキーマ・作業範囲の判定を共有する。フロントエンドにはツール名の固定一覧を置かない。Agent の対応可否を手動実行の条件にしない。

一覧には次を含める。

- ツール名、短い説明、分類、引数スキーマ。
- 読み取り・更新・完了申告など、実行による作用の説明。
- 操作対象の種別・プロジェクト ID・タスク ID・現在のフェーズと表示名、定義と実行条件の変更を検出する情報。

以下は対象の目安であり、実行可能な一覧はバックエンドが現在の状態から決める。

| 操作対象 | ツールの例と条件 |
| --- | --- |
| プロジェクト | `list_events`、`get_event`、`get_file_change`、`get_file_version`、`get_execution_output` |
| 要件定義・仕様整理・実装手順 | イベント系に加え、`list_documents`、`read_document`、`list_chat_sources`、`read_source`、`edit_document`。編集先は各フェーズで許された文書だけ |
| 入力可能な反省会 | 上記に加え、`get_retrospective_signals`。`finish_retrospective` は既存の条件どおり、自動分析が失敗・停止し手動で完了申告できる場合だけ |
| インストラクション管理 | `list_instructions`、`get_instruction`、`update_instruction` |

実装中・終了・完了済みのタスクは、許可されたイベント・文書の参照ツールだけを対象とし、更新・完了申告は表示しない。処理中の排他制御は参照にも適用する。

`acknowledge_events` は LLM の確認済み位置を更新するための通知なので手動メニューには出さない。人が履歴を読んだことによって LLM の未確認範囲を飛ばさない。自動ジョブ専用の `finish_instruction_update` も出さない。実装中・終了で使う完了ツールも今回の手動操作の対象にはしない。

`finish_retrospective` の画面には、分析完了を申告する操作であること、対象の文書版と判断理由を表示する。「実行」をユーザーの明示的な完了依頼として扱い、ツール成功後の確定処理まで行う。ツール名が登録されているだけで完了条件を満たしたことにはしない。

## 実行

実行ボタンで、操作対象・ツール名・引数・操作 ID をバックエンドへ送る。バックエンドが有効性と引数を再検証し、共有の埋め込みツール実行処理を呼ぶ。LLM への送信、CLI セッションの作成・再開、モデルによる引数補完は行わない。

- 対象プロジェクト・タスク・現在のフェーズ・編集権限をバックエンドで検証する。チャットの作成や会話 ID の指定を利用条件にしない。既存処理が会話の参照を必要とする場合はバックエンドで解決し、そのために空の会話を作らない。実行用のパスや任意の実行関数をクライアントに指定させない。
- 一覧取得後にフェーズや編集可否が変わった、作業フォルダーを再指定した、ツール定義が変わった、対象が削除された場合は実行を拒否する。説明と再取得操作を表示し、新しい対象で自動実行しない。
- 通常送信・保守コマンド・自動処理と競合しないよう、既存の排他制御と連携し、プロジェクト・タスク・インストラクションの対象ごとに競合を防ぐ。別タブからの同時実行もサーバーで防ぐ。
- イベント参照の取得上限や文書・指示の固定版など、従来はエージェントのターンが持っていた実行コンテキストを手動操作にも用意する。イベントの上限は実行受付時に固定し、範囲外の参照を拒否する。
- 手動実行で LLM セッションの確認済みイベント位置を進めない。`list_events` の省略時の開始位置は 0 とし、続きは返却されたカーソルをユーザーが指定する。
- `edit_document` の版・引用元・編集可能な文書の検証、`update_instruction` の `expected_content` による競合検出を維持する。競合時は上書きしない。
- 手動操作に必要な準備・確定だけを共有し、エージェントのターン終了処理をそのまま呼ばない。読み取り操作から実装の自動継続や反省会の状態変更を起動しない。
- 完了申告を除く更新ツールは、その更新と既存の変更通知を行う。フェーズの自動移動など、元のツールにない作用を追加しない。

成功は、ツール本体と必要な確定処理が完了し、結果の保存まで確認できた場合とする。受付を成功として表示しない。

## 結果の表示と実行状態

実行後も引数入力に使ったダイアログを開いたままにし、その中にツール名・入力・結果・実行時刻・状態を表示する。実行状態は実行中・完了・失敗・中断・結果不明を区別する。長い出力は既存の上限を適用して省略を明示し、ダイアログ内をスクロールして確認できるようにする。出力は HTML として実行しない。

完了後は「閉じる」または Escape でダイアログを閉じ、ツールボタンへフォーカスを戻す。チャットには実行通知、ユーザー発言、アシスタント発言、ツールパックのいずれも追加しない。失敗・中断・結果不明もダイアログ内で知らせる。

二重実行の防止と通信切断後の照合に必要な操作 ID・対象・入力・状態・結果は、チャット履歴と分けた実行管理用の記録に保持する。会話のメッセージ・パート・`command` には保存せず、チャット取得・パック同期・会話アーカイブにも混ぜない。結果一覧や手動操作の履歴画面は今回追加しない。

手動操作の入力・結果を次の通常送信へ自動添付しない。LLM セッションの確認済みイベント位置も更新しない。ツールによって更新された文書・指示や、その更新に伴う既存の変更イベントは、通常の参照・通知の仕組みに従う。

実行中は同じ対象で競合する送信・コマンド・更新操作を止め、進行状況をツールのダイアログ内に表示する。対象ツールはローカルの読み取り・更新処理であり、初回の実装では途中中断の操作を設けない。ダイアログを閉じても受付済みの処理は取り消さず、再度開いたときに同じ操作 ID で照合する。

通信切断やサーバー再起動で結果を確認できない場合は、自動再実行せず操作 ID から実行状態を照合する。画面の再読み込み後も照合できるよう、受け付けた操作 ID をチャット本文とは別に保持し、状態・結果はツールのダイアログに復元する。受付記録が見つからないなど照合が続けられない場合は、実行済みの可能性を伝え、ユーザーが「照合を終了して閉じる」を選べるようにする。この操作でリクエストを再送しない。同じ操作 ID・同じ入力の再受付では既存の状態を返し、副作用を繰り返さない。同じ ID で異なる入力は拒否する。副作用の完了と結果保存の間で停止した場合も、未実行と推測して再実行しない。

## API

対象・引数・結果は手動ツール専用の API で扱う。

| API | 用途 |
| --- | --- |
| `GET /api/tools` | 操作対象を指定して、その時点の有効なツールと定義を取得 |
| `POST /api/tools` | 操作対象、ツール名、引数、操作 ID、一覧の変更検出情報を渡して直接実行を受け付ける |
| `GET /api/tools/operations/:operationId` | 対象のスコープを検証し、手動操作の状態・結果を取得 |

実行状態と結果は手動操作用 API で取得し、チャット取得・パック同期では配信しない。受付後に HTTP の応答が途切れても、新しい操作 ID で再送する必要がない契約にする。具体的なフィールドは [HTTP API](../communication/http-api.md#手動ツール)、実行記録の保存と 30 日の詳細保持期限は [SQLite](../data/sqlite/README.md#手動ツールの実行記録) に従う。

入力不正、対象不存在、権限・スコープ違反、実行中、定義や対象の状態の変更、ツール実行失敗を区別する。クライアント側の非表示だけに頼らず、非公開・無効・未知のツールを直接 API に指定した場合も拒否する。

## 受け入れ条件

1. Navbar の右側にツールボタンがあり、チャット入力欄の有無にかかわらず専用ダイアログを開ける。狭い画面でも一覧・入力・結果を操作できる。
2. マウス・キーボードで一覧を開閉し、引数入力へ進める。項目選択だけで実行しない。
3. 表示中のプロジェクト・タスク・現在フェーズ・インストラクション管理に応じて対象を明示し一覧を切り替える。ホーム・設定では以前の対象を引き継がない。
4. 必須、任意、列挙、整数、真偽値、`null`、配列・オブジェクトを正しく送信し、不正な引数では実行しない。
5. モデル・接続先の選択や CLI の状態に依存せず、選んだツールを指定引数で一度だけ実行する。Agent の `run`、CLI、実サービスを呼ばない。
6. ツール操作の前後で入力欄の下書きが保たれる。
7. 文書・指示の更新制限、競合検出、イベント・プロジェクトのスコープ制限を直接 API からも守る。
8. 画面・タスク・フェーズ変更や別タブの送信、二重クリックによって古い対象や重複した操作を実行しない。モデル変更・会話リセットではツールの対象が変わらない。
9. 実行状態・入力・結果はツールのダイアログだけに表示し、チャット履歴・パック・コマンド結果には追加しない。再読み込みや再接続では操作 ID で照合し、完了未確認の操作を自動再実行しない。
10. 手動参照で LLM の確認済み位置が変わらず、次の会話に手動操作の入力・結果を自動添付しない。
11. `finish_retrospective` は許可された状態でだけ完了を確定し、読み取りツールから自動処理を開始しない。
12. 既存の Navbar の操作とチャットのコマンド、モデル選択、通常送信、読み取り専用表示が維持される。

検証は、UI テストとバックエンドのスコープ・競合・再受付・復元のテストを含め、最後の編集後に `bun run test` を実行する。チャット連携の検証には既存の偽エージェントを使い、実サービスを呼ばない。
