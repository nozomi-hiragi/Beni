# LLM チャット連携

## 目的と方針

指示書の自動更新や計画・実行の自動化に先立ち、ユーザーが選んだ接続先と Beni の画面で会話できるようにする。Claude Code と Codex は、ユーザー自身が実行環境に公式 CLI をインストールし、自分のサブスクでログイン済みであることを前提とする。Beni はその CLI を利用する。最初に動作確認する接続先はユーザーが決める。接続先は役割と分離し、後から追加・交換できるようにする。

Beni はインストールとログイン状態を確認する。未インストールならインストールを、未ログインならログインを案内し、ユーザーが CLI 側で済ませた後に「更新」で再確認する。Beni 内でログインを開始したり、認証トークンを取得・保存・転送したりしない。認証情報の管理と更新、サービスとの通信は公式 CLI に任せる。

この接続方式の採用は、第三者アプリでのサブスク利用に関する提供元の許諾を確認済みとするものではない。対応する CLI・SDK の利用条件は公式資料に従う。

## 接続方式

### Codex

- 検出したインストール済み Codex CLI の app-server を起動し、構造化された通信で初期化する。会話の作成・再開、発言の送信、回答の逐次受信、エラーや承認要求を扱う。会話の継続に必要な接続先の ID を保存する。
- 接続状態とモデル一覧は、使用する実行環境・アカウントに対して確認する。取得したモデル一覧は利用権限の保証として扱わない。
- ログイン状態は app-server の正式なアカウント情報取得機能で確認する。Beni 自身はログイン操作や資格情報ファイルの読み取りを行わない。CLI が使用中の認証方式を確認し、サブスク以外で動いている場合はその状態を明示して、意図しない API 課金に切り替えない。
- コーディングエージェントにはファイル操作やコマンド実行の機能もある。ジェネラルは読み取り専用とする。タスクチャットは要件定義・仕様整理・実装手順ではタスク専用文書フォルダ内で文書を更新できる。実装中・反省会ではプロジェクト内の文書と実装コードを更新できる。外部ツールの制限は継続する。

### Claude Code

- インストール済みの公式Claude Code CLIを非対話モードで起動し、`stream-json` の部分応答・ツール結果・完了通知を既存のパック配信へ変換する。外部SDKを追加せず、認証とサービスとの通信はCLIに任せる。
- 対応するCLIは2.1.292以降。`--version` と `auth status --json` で状態を確認する。認証方式が `claude.ai`、接続先が `firstParty`、ログイン済みのときに利用する。APIキー・第三者プロバイダーへ自動変更しない。アカウントIDやメールアドレスは保存・返却しない。
- モデル候補はCLIの `sonnet`・`opus`・`haiku` エイリアス。候補の表示はアカウントの利用権限を保証しない。送信時のモデル拒否は警告表示と入力の復元で扱う。
- 同じ接続先の会話はセッションIDで再開する。接続先を切り替えた場合は新規セッションを作り、保存済みの会話本文を参考履歴として引き継ぐ。他の接続先のセッションIDを流用しない。
- `restricted`・`safe-mode` を使い、ユーザーやプロジェクトの追加設定、外部MCP、フック、ブラウザー連携などを無効にする。GeneralではRead・Glob・Grep、タスクではそれらにWrite・Edit・Bashを加える。準備フェーズの作業先はタスク文書フォルダ、実装中・反省会はプロジェクトフォルダとする。
- タスクではCLIのサンドボックス内でシェルコマンドを実行し、テストやビルドにも利用できる。準備フェーズはタスク文書フォルダ、実装中・反省会はプロジェクトフォルダを作業範囲とし、ネットワーク接続とサンドボックス外への再実行を許可しない。サンドボックスを利用できない環境ではコマンド実行を拒否する。
- Claude CLIの既定により、専用の一時フォルダとGit worktreeの共有Git管理領域にも書き込みが許可される。Codexと隔離範囲が完全に同一ではない。管理者が設定したCLIポリシーがBeniの指定より優先される。Linux・WSL2では、Unixソケットの隔離にはCLIの追加seccompフィルタが必要であり、通常のサンドボックス起動成功だけでは保証されない。

接続方式とCLIオプションは [Claude Code CLIリファレンス](https://code.claude.com/docs/en/cli-reference)、コマンドの隔離は [Claude Codeサンドボックス](https://code.claude.com/docs/en/sandboxing) に従う。

### 将来の接続候補

Sign in with ChatGPT による直接連携、通常の API キーによる OpenAI API、その他の接続先は追加候補として残す。初期の CLI 接続にはアプリ独自の認可管理を含めない。接続できないときに別の接続先・認証方式・課金方式へ自動で切り替えない。

Sign in with ChatGPT を追加する場合は、対象となるオープンソースアプリの利用資格、登録・認可、対応モデルを確認する。Responses API の現行プレビューでは `store: false` と `stream: true` を指定し、必要な会話履歴を要求ごとの `input` に含める。実装時に最新の制約を再確認する。

## 会話と画面

FE・BE 間の配信・確定・再接続は [チャットのパック同期](../communication/chat-sync.md) に定義する。この文書は CLI 連携、画面の要件、BE の履歴保存を扱う。

- モデルの選択は会話ごと（タスクではフェーズごと）に保存する。利用できない選択は `⚠️` 付きで残し、送信・実装開始を止める。詳細は [チャットのモデル選択](../objects/chat.md#モデルの選択) に従う。
- 接続先・モデルを選び、ユーザー発言と回答を表示する。応答は受信途中も更新し、完了・失敗・中断・結果不明を区別する。
- 会話は daisyUI の Chat で表示し、ユーザー発言を右、エージェントの返答を左に配置する。実行中は Aura と「作業中」の表示を出し、本文の受信前やツール実行中も継続する。
- チャットが最下部にある間は内容の追加に追従する。ユーザーが上へスクロールしたら追従を止め、最下部へ戻ると再開する。会話を切り替えたときは最下部から表示する。
- タスクの各フェーズに対応するチャットとプロジェクトのジェネラルチャットを別の会話として扱い、表示、履歴、接続先の会話 ID が混ざらないようにする。
- チャット履歴は当面、人が直接開いて確認できる整形済み JSON ファイルに保存する。詳細は下記の保存方針に従い、画面の再読み込み後も履歴を確認できるようにする。
- 設定画面では、実行ファイルの検出、認証の状態、モデル一覧、利用枠をそれぞれ区別して表示する。確認できない項目は未確認とし、未取得を利用可能と断定しない。
- 要求が未送信と分かる場合と、送信されたか不明な場合を分ける。結果不明を自動で再送せず、重複送信のリスクを抑える。停止や再接続では、処理が終了したと確認できない限り完了と見なさない。

## スラッシュコマンド

入力欄で `/` からコマンド名を入力すると、入力欄の上にポップアップで候補を表示する。チャットや入力欄の配置は変えず、候補はクリックまたはキーボードで選択できる。入力欄からフォーカスが外れるか Escape を押すと閉じる。コマンドは通常の発言と分けて処理し、未対応の名前や引数をLLMへそのまま渡さない。本文途中やコードとして書かれた文字列、ファイルの絶対パスは通常の文章として扱う。

候補は選択中のモデルの接続先に合わせて切り替える。接続先の専用コマンドは、対応するモデルを選んだ場合だけ表示する。モデル未選択時はBeni内で処理できる共通操作を表示する。タスク名変更はタスク会話のみ、生成を伴うコマンドはGeneralと入力可能なタスク会話のみとする。CLIの対話画面、認証・権限・外部設定の管理、クラウド実行を操作するコマンドはBeniのチャットには含めない。

| コマンド | 対応 | 動作・引数 |
| --- | --- | --- |
| `/help` | 共通 | 現在使えるコマンドの説明を表示 |
| `/status` | 共通 | 選択モデルと会話の接続先・状態を表示 |
| `/model [接続先/モデルID]` | 共通 | モデルを選択。引数省略時は選択欄へ移動 |
| `/compact` | 共通 | 会話のLLMコンテキストを圧縮。引数なし |
| `/clear` | 共通 | 確認後、履歴をアーカイブして新しい会話へ切り替える。`/new`・`/reset` も同じ |
| `/copy` | 共通 | 最新の完了済み回答の本文をクリップボードへコピー |
| `/export` | 共通 | 現在の会話をMarkdownとしてダウンロード |
| `/rename <名前>` | 共通・タスクのみ | タスク名を変更し、タブ・タスク一覧へ反映 |
| `/review [対象]` | 共通 | 変更をレビュー。Codexでは対象省略時に未コミット変更を対象とする |
| `/recap` | 共通 | 会話の目的・決定事項・未解決事項などを要約 |
| `/context` | Claude | CLIセッションのコンテキスト使用状況を表示 |
| `/usage` | Claude | 使用量を表示。`/cost`・`/stats` も同じ |
| `/code-review [対象]` | Claude | CLI組み込みのコードレビューを実行 |
| `/simplify` | Claude | コードの再利用・簡潔さ・効率を見直す |
| `/security-review` | Claude | 変更のセキュリティ上の問題をレビュー |

`/help`・`/status`・`/model`・`/copy`・`/export` はフロントエンド内で処理する。`/rename` は既存のタスク名変更APIを使う。これらをLLMへの発言に変換しない。コマンドの結果は通常の回答パックとは分け、チャット履歴内に折りたたんで表示する。必要なときだけ本文を開き、閉じるボタンで表示を消せる。結果を入力欄の上に固定して会話領域を狭めない。

Claudeの `/context`・`/usage` は、CLIが返すコマンド識別情報付きの出力を表示する。通常のモデル応答を情報表示の代わりに使わない。コマンドの本文を受信しても、処理の正常終了を確認するまでは成功としない。

`/review`・`/recap` など生成を伴うコマンドは、選択中モデルに対して通常の会話と同じ保存・配信・中断・作業範囲の制限を適用する。Codexのレビューは `review/start`、要約は要約用の依頼として実行する。Claudeでは対応する組み込みコマンドを実行する。レビューのクラウド実行や外部投稿を指定する引数は受け付けない。

圧縮・コンテキスト表示・使用量表示は保存済みCLIセッションを操作する。選択モデルと保存済みセッションの接続先が違う場合は409で拒否する。別の接続先の会話へ操作を流用せず、通常の発言を送って接続先を切り替えるか、`/clear` で新しい会話を始める。

`/compact` は、現在の会話に保存されているCLIセッションを対象にする。インストラクション編集画面のフォーカスを変更する操作ではない。General、タスクの入力可能なフェーズ、インストラクション編集相談で使える。まだCLIセッションのない会話、実装中・完了済みのタスクでは実行しない。

Codexでは保存済みスレッドを再開して `thread/compact/start` を呼び、圧縮項目とターンの正常終了を確認する。Claudeでは保存済みセッションを再開して組み込みの `/compact` を実行し、手動の `compact_boundary` と処理の正常終了を確認する。両方を確認してから成功とし、CLIの受付や成功応答だけでは完了としない。追加スキルや外部ツールは有効化しない。

Claudeの通常送信では `--disable-slash-commands` を付ける。対応コマンドの実行時だけこの指定を外し、Beniが認識した名前と引数からコマンドを組み立てる。`--safe-mode` と設定読み込みの無効化は維持する。圧縮・情報表示ではツールを無効にし、生成コマンドでは通常の会話と同じツール・作業範囲に制限する。実行環境での未対応や履歴不足が確認できた場合は、汎用の失敗表示に置き換えず、固定の説明文で理由を表示する。

圧縮中は追加送信、重複実行、タスクのフェーズ変更を止め、中断を可能にする。画面には圧縮中・完了・失敗・中断・結果不明を区別して表示する。切断や再起動で完了を確認できなければ結果不明とし、自動再試行しない。

Beniに保存したメッセージとパックは圧縮操作で変更しない。操作の最新状態と情報表示結果は会話に別項目として保存する。`/clear` では元の会話JSONを同じ保存ディレクトリの `history/<会話ID>.json` に残し、新しい会話IDと空の履歴へ切り替える。インストラクション編集相談では適用中の編集用指示を引き継ぐ。APIと通知は [HTTP API](../communication/http-api.md#チャットのコマンド) に従う。

## チャット履歴の保存

- 会話 JSON にはパック列も保存し、パック ID・順序・確定内容を維持する。パックの形式とハッシュは [HTTP API](../communication/http-api.md#パックの形式とハッシュ) に従う。
- 会話ごとに一つの JSON ファイルを持ち、形式のバージョン、会話 ID、プロジェクト ID、タスク ID（ジェネラルは null）、フェーズ（ジェネラルは null）、最後にエージェントへ渡した変更イベントID、発言 ID、送信 ID、発言者、本文、接続先、モデル、CLI 側のセッション ID、送受信時刻、処理状態を記録する。接続先やモデルを変更しても過去の発言の情報を上書きしない。
- Beni の会話 ID と CLI 側のセッション ID は区別し、別の会話のセッションを再利用しない。CLI 側で再開できない場合も、保存した会話は閲覧できる。
- 一つの会話への更新は直列化し、一時ファイルへの書き込み後に置き換えて破損を防ぐ。送信前に記録し、途中応答も適度に保存する。再起動時に実行継続を確認できない要求は結果不明として扱い、自動再送しない。
- JSON はプロジェクトの `.beni/chat/` に保存し、ソースコードやナレッジの Git 管理に含めない。トークン、API キー、ログインコードなどの秘密情報は保存しない。チャット履歴の正本はこの JSON とする。配置は [会話保存仕様](../data/beni/chat.md) に従う。

## 実装順と検証

1. 既存のチャット画面に JSON での会話保存を接続し、接続先を差し替え可能にする。偽の接続先で送信・逐次表示・履歴・中断を確認する。
2. 設定画面にインストール・ログイン状態と「更新」を実装する。ユーザーがインストール・ログインした CLI を、選択した接続先で実際の会話まで接続する。
3. 会話の継続や失敗・結果不明の復旧を確認する。その後、指示書の自動更新や計画・実行の流れへ組み込む。追加した接続先が対応していない操作は未接続・未対応として表示する。

未インストール・未ログイン・検出失敗と更新後の状態遷移、JSON の保存失敗・再読み込み・同時更新、プロジェクト／タスク間の混入、二重送信、通信断、途中応答、更新・画面移動後の状態、誤った接続先への自動切替がないことを検証する。実サービスの利用可否とモデルのアクセス権は、実際に選んだ環境で確認する。

## タスク文書の実ファイル

- プロジェクト作成時、選択した既存フォルダに `.beni/tasks/` を作る。タスク作成時に `.beni/tasks/<task-id>/requirements.md`、`documents.md`、`implementation.md` を用意する。タスクIDは [共通ID規則](../data/README.md#idの共通規則) を使い、名前の重複に影響されない。追加文書の名前は英語の小文字・数字・ハイフンと `.md` を使う。
- 文書の正本は実ファイルとする。保存場所と復元の規則は [プロジェクトの .beni](../data/beni/README.md) に従う。
- 文書プレビューは Markdown を装飾して表示する。見出し・箇条書き・表・引用・コードブロックなどに対応し、生コードへの切り替えは設けない。HTML は表示前にサニタイズする。絶対 HTTP/HTTPS リンクは別タブで開き、同じタスク内のMarkdownへの相対リンクは文書プレビューで開く。対象のないリンクやタスク外への相対リンクは遷移させない。画像は外部取得せず代替テキストを表示する。
- 文書フォルダの変更を監視してプレビューを更新する。atomic renameによる置換も検知し、未変更のメッセージ・タブのDOMを維持する。通知と再取得の手順は [WS メッセージ仕様](../communication/websocket.md) を参照する。
- タスクのCodexにはプロジェクトの参照パス、タスク専用文書パス、文書更新の指示を伝える。新規会話・再開の両方で、最新のフェーズをバックエンドで確認し、作業ディレクトリと書き込み許可先を要件定義・仕様整理・実装手順では当該タスクフォルダ、実装中・反省会ではプロジェクトフォルダに設定する。シェルとその実行基盤である Code Mode host は許可した範囲の作業に利用可能とし、ネットワーク・MCP・追加エージェントなどは無効のままにする。承認による範囲外への昇格は許可しない。一般チャットでは従来どおりツールを無効にする。
- `.beni` 以下の管理ディレクトリや文書がシンボリックリンクの場合は処理を拒否する。文書は通常ファイルのみ扱い、1ファイルのプレビュー取得は1MiBまでとする。初期化に失敗した場合は、完成したタスクやプロジェクトとして登録しない。
- 文書が変更されるか・内容が適切かはモデルの実行結果に依存する。中断時までの書き込みは残り、自動で巻き戻したり、再送したりしない。サンドボックスはフェーズに応じたフォルダ内に書き込みを制限するもので、Markdown以外を完全に禁止する拡張子フィルターではない。実モデルによる書き込みとOSサンドボックスの動作は実環境での確認が必要。

## フェーズ別の会話と変更の引き継ぎ

タスクの5フェーズはそれぞれ独立した会話・接続先セッションを持つ。フェーズを戻したらその会話を再開し、文書は共有したままにする。送信ごとにプロジェクトの未確認イベント範囲をエージェントへ知らせ、埋め込みツールで取得させる。確認完了通知があるまでカーソルは進めない。取得範囲・文書の版・失敗時の扱いは [タスクの変更履歴](../objects/task-events.md) に従う。

## 実装の終了と反省会

実装中はユーザーの追加入力を受けず、開始時の定型依頼をゴールまで実行する。停止以外で実行が終了したら反省会へ移る。反省会では実装結果とタスク文書を参照し、手直し・検証・振り返りを行う。実装終了とタスク完了を区別し、完了・再開と実装担当モデルの選択は [タスク仕様](../objects/task.md) に従う。

## 共通・フェーズ別の指示

LLMへの追加指示は、アプリSQLiteに保存した全共通と現在のフェーズのMarkdownから組み立てます。変数と管理画面での閲覧は [インストラクション管理](instructions.md) を参照してください。
