# プロジェクト内ターミナル

プロジェクト内ターミナルの動作を定義します。実装後もこの文書を仕様として維持します。

## 対象範囲

プロジェクト画面からシェルを起動し、コマンドの入力と出力の確認ができるようにします。ターミナルタブとシェルを一対一で対応させ、複数のシェルを切り替えて使います。

プロジェクトのステータス欄への表示、エージェントからの操作、外部向けの詳細なシェル状態取得は対象外です。サーバー再起動をまたぐシェルの維持も対象外です。

## シェルとタブのライフサイクル

- シェルはバックエンドの動作するマシンで実行します。閲覧しているスマートフォンやPC側には起動しません。
- 起動するシェルはサーバー側の `SHELL` 環境変数を使い、未指定なら `/bin/sh` を使います。対話モードで起動します。
- シェルの初期作業ディレクトリは、対象プロジェクトに登録されたフォルダーです。タスク単位ではなくプロジェクト単位で管理します。
- ターミナルタブを追加するとシェルを起動します。既存タブへ戻っただけでは、新しいシェルを起動しません。
- タブの明示的な終了操作で、対応するシェルを終了します。
- タブ切り替え、プロジェクト画面からの移動、ブラウザーの再読み込み・終了、WS切断は、ターミナルタブの終了とは区別します。これらだけではシェルを終了しません。
- 再接続時はバックエンド上の一覧を取得し、残っているシェルへ接続し直します。
- 入力・出力・リサイズ・終了通知には既存の共通WSを使います。ターミナル専用の別WSは作りません。

## 画面

配置と共通タブバーの規則は [プロジェクト詳細画面](../screens/project-detail.md) に従います。チャットの下にターミナルを置き、タブの追加・選択・終了を提供します。

接続中・再接続中・実行中・終了済み・起動失敗を区別して表示します。通信が切れている間は入力を無効にし、キー入力をためて再接続後に送信することはしません。

シェルが自然終了した場合は、終了コードと最後の画面を表示してタブを残します。再実行するときは新しいタブを追加します。

終了失敗を成功扱いしてタブだけ消すことはしません。

## 複数画面の操作権

操作権はシェルごとに一つだけです。誰も操作権を持っていない場合は、最初にそのシェルへの接続・購読が成立した画面が自動取得します。「乗っ取る」を押す必要はありません。同時に開いた場合も、バックエンドが順序を決め、一つの画面だけへ与えます。すでに操作権を持っている画面があれば、その画面が保持します。後から同じシェルへ接続した画面は閲覧専用になり、出力だけを受信します。接続しただけで操作権や端末サイズを変更しません。

閲覧専用の画面には「乗っ取る」ボタンを表示します。押すとバックエンドが旧画面の操作権を失効させ、新しい画面へ操作権を移します。新しい画面は権限取得の応答を受けてから入力を有効にします。旧画面は閲覧専用へ切り替わり、出力の受信は続けます。シェルや実行中のコマンドは再起動しません。

操作権を持つ画面の切断・購読解除をバックエンドが確認したら、その操作権を解放します。シェルは終了しません。再接続も新しい接続として扱い、権限が空いていれば自動取得し、別の画面が保持していれば閲覧専用になります。すでに閲覧中の画面へは自動移譲せず、その画面からは「乗っ取る」で取得できます。

シェルの明示的な終了も操作権を持つ画面だけに許可します。閲覧専用画面から終了したい場合は、先に「乗っ取る」で操作権を取得します。終了済みタブを一覧から削除する場合も、操作権を取得してから閉じます。

入力とリサイズは操作権を持つ画面だけに許可し、PTYの列数・行数はその画面に合わせます。権限の検査と入力の受け付けはバックエンドで行い、UIの無効化だけに依存しません。

操作権の移譲はシェル単位で直列に処理し、同時に二つの画面へ与えません。接続と権限の世代を識別し、移譲後に届いた旧権限の入力・リサイズは拒否します。移譲前にすでにPTYへ渡した入力は取り消しません。

## バックエンドの責務

バックエンドがセッションID、プロジェクトID、実行状態、PTYとシェルの対応を管理します。ブラウザー側の接続IDをシェルの識別子には使いません。購読解除は出力の受信停止であり、シェルの終了操作ではありません。

明示的な終了では、シェル配下のプロセスとジョブのプロセスグループを確認して終了を要求し、250ミリ秒後に残った対象へ強制終了を送ります。サーバーの通常終了でも、自身が起動したシェルを片付けます。

自分でデーモン化してシェルとの親子関係・セッションを離れたプロセスや、サーバーの強制終了後の回収は保証しません。自然終了したシェルの古いPIDを使って、後から別のプロセスを終了させることはしません。

ブラウザーから任意の起動コマンドや作業ディレクトリを指定するAPIにはせず、登録済みのプロジェクトとの対応を検証します。シェル操作はバックエンドのユーザー権限で動作するため、既存のホスト・Origin検査を維持し、Tailscale経由のアクセス制御も引き継ぎます。入力・出力をアプリケーションログや永続履歴へ自動保存しません。

## 画面の復元

バックエンドはPTYからの出力をheadless端末で解釈し、現在の画面と上限付きスクロールバックを保持します。ブラウザーが接続し直したときは、この画面を復元してから後続の出力を適用します。過去の出力文字列の末尾だけを途中から再生する方式にはしません。

画面復元が完了するまで入力を受け付けません。復元内容と出力の順序を検証し、欠落や重複を検出したときは再同期します。既存のシェルを起動し直して復旧したように見せることはしません。

## 通信の役割

一覧取得・作成・終了などの管理操作はHTTP、入力・出力・リサイズ・終了通知は共通WSを使います。入力とリサイズは対象を検証する専用メッセージとし、任意のHTTP操作を呼ぶ汎用RPCにはしません。

作成や入力は、通信失敗時に無条件で再送しません。作成結果が不明な場合は、バックエンド上の状態と照合します。

共通の接続・購読・エラー処理は [通信仕様](../communication/README.md) に従います。
