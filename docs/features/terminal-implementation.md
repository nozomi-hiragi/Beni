# ターミナルの実装計画

実装中だけ使う文書です。現行との差分、未決定事項、実装順序、検証をここに集約します。決定した動作は [確定仕様](terminal.md)、API契約は [通信仕様](../communication/README.md) に反映します。実装と検証が完了したら、この文書と目次のリンクを削除します。

## 現状と実装範囲

共通WSにはチャットと文書更新の購読があります。ターミナルのPTY管理、入出力メッセージ、画面は未実装です。既存の `work/terminal` は参考にし、現在のソース配置と共通通信に合わせて実装します。

まずプロジェクト画面でターミナルを利用できるところまで実装します。プロジェクトのステータス表示と外部向けの詳細なシェル状態取得は含めません。

## 画面の検討案

シェルが自然終了した場合は、終了コードと最後の画面を確認できるよう終了済みタブを残し、再実行には新しいタブを追加する案です。保持期間と明示的に閉じた場合の扱いを決めてから確定仕様へ反映します。

## 通信の追加案

通常の管理操作はHTTP、継続的な入出力はWSという既存の役割分担を維持します。以下は契約案であり、既存の実装済みAPI一覧にはまだ追加しません。

| 操作 | 通信 | 内容 |
| --- | --- | --- |
| 一覧取得 | HTTP | プロジェクトに属するセッションIDと状態を取得 |
| 作成 | HTTP | プロジェクトと初期の列数・行数を指定し、セッションIDを取得 |
| 終了 | HTTP | セッションIDを指定し、対応するシェルを終了 |
| 購読 | 共通WS | プロジェクトIDとセッションIDを検証して購読 |
| 操作権の取得・移譲 | 共通WS | 「乗っ取る」の要求を処理し、権限変更を通知 |
| 入力 | 共通WS | 操作権と世代を検証して端末入力を送信 |
| リサイズ | 共通WS | 操作権を持つ画面の列数・行数をPTYへ反映 |
| 出力・終了通知 | 共通WS | 対象の出力と終了状態を通知 |

HTTPのパス、WSのメッセージ名、上限値、エラーは、実装前に [通信仕様](../communication/README.md) へ反映します。入力・リサイズは汎用HTTP RPCではなく、型と対象検証を持つ専用メッセージとして共通層に追加します。

作成や入力は、通信失敗時に無条件で再送しません。作成結果が不明なら一覧と照合します。同じシェルを重複して起動しないための作成要求IDの扱いは、管理APIを定義するときに詰めます。

## 次に詰める点

1. **再接続後の画面復元**：チャットと違い、端末の制御シーケンスは途中から表示するだけでは画面が崩れます。画面状態の復元か、上限付き出力バッファの再生を選び、初期取得中の出力との順序・重複・欠落も定義します。
2. **閲覧専用画面の終了操作**：操作権の自動取得・排他・乗っ取り・切断時の解放は確定仕様に従います。閲覧専用画面からシェルを終了する操作を許可するかは別途定義します。
3. **PTYと描画ライブラリ**：バックエンドのPTY、フロントエンドの端末描画は既存ライブラリを利用する方針です。BunとmacOS・Linuxでの動作、ライセンスを確認して選定します。既存の `work/terminal` は参考にし、現在の共通通信へ合わせます。
4. **シェルと終了処理**：起動するシェルの選び方、終了要求の猶予・強制終了、自然終了したセッションの保持期間を決めます。
5. **負荷制限**：セッション数、入出力サイズ、出力バッファ量を制限します。遅い接続に対して共通WSを切断する場合も、シェルの存続と再接続時の画面回復を分けて扱います。

## 実装時の確認項目

- 作成したシェルの作業ディレクトリがプロジェクトのフォルダーになっている。
- 複数タブの入出力が混ざらず、別プロジェクトのセッションは操作できない。
- タブを閉じるとシェルが終了し、実行中の子プロセスを取り残さない。
- 画面移動・再読み込み・WS切断ではシェルが終了せず、再接続して利用できる。
- 自然終了と起動失敗を表示し、失敗時に架空の実行中タブを残さない。
- 入力・リサイズ・出力の順序と上限が守られ、通信エラーで入力を重複実行しない。
- 操作権が空いている場合は、最初に購読が成立した画面だけが自動取得する。再接続でも同じ規則を適用する。
- 所有者の切断・購読解除で権限は解放されるが、シェルは終了せず、既存の閲覧画面へ勝手に移譲しない。
- 後から接続した画面は閲覧専用となり、既存の操作権と端末サイズを変えない。
- 「乗っ取る」で旧画面の入力権が失効してから新画面の入力が有効になり、両画面は出力を受信し続ける。
- 同時の乗っ取り要求や遅れて届く旧権限の入力・リサイズでも、二重に操作を受け付けない。
- チャット・文書通知と同じWSを共有しても、既存の通信が動作する。

## 実装順序

1. 画面復元・閲覧専用画面の終了操作・自然終了の扱いを決め、確定仕様に反映する。
2. PTYと描画ライブラリを選定し、対象OSで起動・入出力・子プロセスを含む終了を確認する。サーバーの強制終了時の制約も確認する。
3. HTTP管理APIとWSメッセージの型・検証・上限・回復手順を通信仕様に定義する。
4. バックエンドのセッション管理と共通通信への登録を実装する。
5. ターミナル画面とタブ操作、再接続を実装する。
6. 上記の確認項目と既存テストを実行し、仕様と実装の一致を確認する。
7. 確定事項と必要な制約が恒久文書に残っていることを確認し、この実装計画を削除する。
