# インストラクション管理

LLMに渡すBeniの指示を、アプリ共通のMarkdownテンプレートとして管理します。プロジェクトや会話の本文とは別のデータです。

## 管理単位

| キー | 表示名 | 役割 |
| --- | --- | --- |
| `editor` | 編集相談用 | ユーザーと指示を検討し、合意した変更を保存する |
| `common` | 全共通 | 決定事項の尊重、イベントの参照、正確な報告など |
| `requirements` | 要件定義 | 目的、制約、未解決事項、完了条件の整理 |
| `documents` | 仕様整理 | `documents.md`と追加文書を使った資料・仕様の整理 |
| `implementation` | 実装手順 | 実装順序と検証方法の整理 |
| `execution` | 実装中 | 合意した仕様と手順に沿った実装・検証 |
| `retrospective` | 反省会 | 動作確認、手直し、振り返り |
| `finalization` | 終了 | 反省会から確定した学びを抽出し、プロジェクトのナレッジに反映 |
| `task.completed` | タスク完了 | タスク完了イベントに対応して実行する手順・判断 |

タスクの会話には「全共通＋現在のフェーズ」を結合して渡します。Generalには全共通のみを渡します。Codexでは `developerInstructions`、Claudeでは追加システムプロンプトとして渡し、CLI自身の基本指示は置き換えません。権限やツールの有効化は従来どおりバックエンド側で制御します。

## 保存と初期値

アプリのSQLiteでキーごとの文書項目、根拠、参照と版を管理し、項目を連結してMarkdown本文を組み立てます。初期値と既存の本文はDB初期化時に取り込みます。タスク完了イベントに対応するワークフローの実行も同じDBに保持します。詳細は [要求・根拠を追跡できる文書管理](../traceable-documents-design.md) を参照します。

プロジェクト固有のパス、ナレッジ本文、会話内容などはテンプレートに保存しません。送信時にその会話の値を埋め込みます。

## 変数

変数は `{{変数名}}` と記述します。式や条件分岐を実行するテンプレート言語にはしません。

| 変数 | 値 |
| --- | --- |
| `{{project_directory}}` | プロジェクトのディレクトリ |
| `{{working_directory}}` | そのフェーズの作業ディレクトリ |
| `{{task_id}}` | タスクID |
| `{{task_directory}}` | タスク文書を埋め込みツールで参照する案内。既存テンプレートとの互換用 |
| `{{phase}}` | 現在のフェーズの内部名 |
| `{{knowledge_path}}` | プロジェクトナレッジを埋め込みツールで参照する案内。既存テンプレートとの互換用 |
| `{{knowledge_content}}` | プロジェクトナレッジの本文の抜粋 |
| `{{execution_chat_path}}` | 添付された実装中チャットの抜粋を参照する案内。反省会の既存テンプレートとの互換用 |
| `{{retrospective_chat_path}}` | 添付された反省会チャットの抜粋を参照する案内。終了の既存テンプレートとの互換用 |

置換は一度だけ行い、埋め込まれた本文中にある変数らしい文字列は再評価しません。未知の変数や、その会話で値を用意できない変数はエラーとして扱い、不完全な指示を送信しません。General用の全共通にはタスク専用の変数を含めません。

## 編集相談チャット

プロジェクトに属さないアプリ共通の会話を一つ持ち、CodexまたはClaudeを選んでインストラクションを相談・更新できます。会話履歴はアプリデータの `chats/<chatId>.json` に保存します。

### 編集対象のフォーカス

編集相談用、全共通、各フェーズ、ワークフローのプロンプトをクリック、またはEnter・Spaceで選択します。初期状態は未選択です。選択中の本文をオーラで示し、チャットカードの上部にフォーカスの対象名を表示します。タブの表示切り替えだけではフォーカスを変更しません。

未選択では送信できません。送信ごとに `instructionFocus` として対象キーをバックエンドに渡します。これは相談対象を示す情報であり、ユーザーが入力した本文は変更しません。

バックエンドは直近に送信を受理された対象を会話の `lastInstructionFocus` に保存します。初回の送信、前回から対象・保存本文・CLIセッションのいずれかが変わった送信では、対象のキーと変数未展開の本文をLLMへの入力に添えます。受理された送信時点の本文ハッシュも保存します。送信前の失敗や開始拒否では前回の対象を更新しません。

専用の `editor` 指示を追加システムプロンプトとして使い、通常の全共通・フェーズ指示は混ぜません。指示一覧や全本文は毎回送信しません。フォーカス通知にない情報は、必要に応じて専用の取得ツールで参照します。編集相談用の指示自体もDBで管理します。会話には適用済みの本文を保存し、編集しても「適用」を押すまでは現在の指示で会話を続けます。`editor` では変数展開しません。

### 編集相談用の埋め込みツール

| ツール | 引数 | 戻り値 |
| --- | --- | --- |
| `list_instructions` | `{}` | `{instructions: [{key, name}]}`。管理する9種類のキーと表示名。本文は含めない |
| `get_instruction` | `{key, revision?, item?, offset?}` | `{key, revision, item, next}`。指定版の項目を分割取得する。版の省略時は最新の保存版 |
| `list_chat_sources` | `{offset?}` | `{sources: [{kind, id, role, excerpt}], next}`。現在の編集相談の発言を引用元として一覧する |
| `read_source` | `{kind, id, revision?, offset?}` | `{text, next}`。指示の項目または編集相談の発言の原文を分割取得する |
| `update_instruction` | `{key, revision, edits}` | 保存した `{key, revision, variables}` |

この5ツールを編集相談チャットとインストラクション管理の手動ツールで利用できます。`get_instruction` の編集用本文は未適用の変更も含む保存済みの値であり、会話に適用中の指示とは区別します。取得した本文や発言は編集対象・引用元のデータとして扱います。未知のキーや余分な引数は拒否します。

`get_instruction` の `item` は0始まりの項目番号、`offset` は項目本文内のUTF-16オフセットです。返された `next` をたどり、続きを取得するときは同じ `revision` を指定します。各項目は編集に使う `id`、本文の `text`、採用理由の `reason`、保存された引用の `sources`、この項目自体を引用するための `source` を持ちます。本文は1回4096 UTF-16単位までで、サロゲートペアの途中では分割しません。保存された引用の本文は先頭256 UTF-16単位までを返し、省略時は `textTruncated: true` と原文の長さ `textLength` を付けます。取得した引用の抜粋をそのまま再保存せず、変更しない引用は `sources` を省略して維持します。最後まで取得すると `next` は `null` です。

指示の引用元は `kind: "instruction"`、`id: "<key>/<item-id>"` とその `revision` で指定します。編集相談の発言は `list_chat_sources` が返す `kind: "message"` と `id: "instructions/<chat-id>/<message-id>"` を使い、`revision` は指定しません。一覧は現在の会話のユーザー発言と確定済みアシスタント発言を新しい順に20件ずつ返し、抜粋は160 UTF-16単位までです。編集相談に属する保存済みの発言は、会話がアーカイブされた後もIDを指定して取得できます。`read_source` で取得した原文の連続した範囲を引用します。プロジェクトやタスクの会話は、この編集相談の引用元として読み出せません。

`update_instruction` は項目ごとの差分を保存します。`edits` の各要素には `id`、`text`、`reason`、`sources`、`index`、`remove` を指定できます。

- 新規項目は `id` を省略し、既存項目の編集には取得済みの `id` を指定します。
- 空白以外の本文を追加・変更するときは、採用理由の `reason` と原文引用の `sources` を明示します。各引用は `{kind, id, revision?, start?, text}` です。サーバーは引用先の所属と、引用文・位置が原文に一致することを検証します。
- 本文を変えず、採用理由や引用だけを変更することもできます。指定しない項目の本文・ID・根拠・引用は維持します。初期設定や移行元の参照を持つ項目の根拠を変更するときは、指示項目の版とID、または編集相談の発言を引用元に指定し直します。
- `index` は対象項目を元の位置から取り除いた後の、0始まりの挿入位置です。並べ替えだけなら根拠を再入力する必要はありません。
- 削除は `{id, remove: true}` で指定します。改行や空白も項目の本文として保持します。

変更前の `revision` が最新版と一致しなければ競合として拒否します。本文が同じで根拠だけが変わっていた場合も競合になります。競合時は最新版を読み直し、既存の変更を保って更新を作り直します。一つでも不正な編集があれば、同じ要求内の変更は保存しません。本文全体を渡す旧形式の `content`・`expected_content` は受け付けません。

保存成功時の `variables` は、結合後の本文中で置換変数として認識した名前をキー、出現位置の配列を値にした辞書です。同じ変数の出現も省略せず、本文の出現順で位置を並べます。位置は保存したMarkdown上の `{{` の開始位置を示す `line`・`column` で、どちらも1始まりです。列はUnicodeコードポイント単位で数え、CRLFも1回の改行として扱います。変数がない場合と、変数を解釈しない編集用の `editor` では `{}` を返します。

対象は管理する9キーに限定します。項目を連結した本文は空白のみ不可、UTF-8で64KiB以下です。共通・フェーズの指示は既知で利用可能な変数のみを許し、不正な更新は保存しません。指示全体の削除・初期値リセットは設けません。保存成功はチャットの通知を通じて画面へ伝え、表示中の指示を再取得します。

CLIの作業先はアプリデータ内の `instruction-editor/` とし、読み取り専用で起動します。このチャットはファイル・DBを直接編集せず、専用ツールだけで保存します。プロジェクトイベント用の6ツールは登録しません。ユーザーとの会話、ストリーミング、パックの確認、中断、モデル選択は既存チャットの仕組みを使います。

ツール定義の変更時は、既存のCodex・Claudeセッションにも新しい定義を反映します。保存済みの編集用プロンプトに旧形式の説明が残っていても、送信時に最新のツール契約を補足します。ユーザーが編集したプロンプトの本文は自動で書き換えません。

### 編集用プロンプトの適用

保存された編集用プロンプトと会話に適用済みの本文が異なる場合、フォーカス表示の右側に「適用」を表示します。生成中・送信準備中は適用できません。ボタンを押すと最新の編集用プロンプトを適用し、履歴が空の新しい会話に切り替えます。LLMへの送信は自動では行わず、次のユーザーメッセージで新規セッションを開始します。モデル選択は保持し、前のLLMセッションやフォーカス通知履歴は引き継ぎません。

前の会話はアプリデータの `chats/<chatId>.json` に同じIDのままアーカイブとして保存します。適用済み本文と未適用の変更は再起動後も判定できます。保存本文が画面の取得時点から変わっていた場合や適用に失敗した場合は、現在の会話を維持してエラーを表示します。ほかの画面にも会話の切り替えを通知します。変更がない状態での再適用では会話を作り直しません。

## 管理画面

独立した管理画面 `/instructions` を設け、ヘッダーの設定ボタンの左にある「インストラクション管理」ボタンから開きます。URLへの直接アクセスとブラウザーの戻る・進むに対応します。

ページ本文の大見出しは置かず、ヘッダーに「インストラクション管理」を表示します。管理画面全体をヘッダーを含む表示領域内に収め、ページ全体ではなく各カード内でスクロールします。狭い画面では本文領域内で縦にスクロールできます。広い画面では左右に分け、中央のハンドルで幅の比率を変更できます。初期値は50:50、左側の幅は20〜80%です。ハンドルはドラッグと左右矢印・Home・Endで操作できます。狭い画面ではハンドルを隠して縦に並べます。

左側は次の順に表示します。広い画面ではチャットと変数・ツールの間に高さ調整ハンドルを置き、初期比率は80:20とします。各パネルの内容は内部でスクロールでき、ハンドルはドラッグと上下矢印・Home・Endで操作できます。

1. インストラクションを一緒に検討・編集するチャット
2. 変数・埋め込みツールの参照カード

左下の参照カードと右側のプレビューカードには、プロジェクト画面と同じ形のタブをカード上端に配置します。

左下の参照カードには独立した「編集用」「インストラクション」「ワークフロー」のタブを設けます。初期表示はインストラクションです。右側の表示タブやチャットのフォーカスとは連動しません。編集用には編集相談専用の5ツールを表示し、変数は現時点では「なし」とします。今後編集用の変数を追加した場合は、このタブの変数欄に表示します。インストラクションには9種類の変数の意味を示すバッジと、プロジェクトチャット用の6ツールを表示します。ワークフローには利用可能な変数と文書参照・編集・完了申告ツールを表示します。置換用の記法や実値は一覧に表示しません。

右側のカードは広い画面で左側と高さを揃え、本文はカード内でスクロールします。「編集用」「インストラクション」「ワークフロー」のタブで表示を切り替えます。編集用には編集相談用のシステムプロンプトを表示します。インストラクションには全共通のMarkdownを上部に置き、その下の6フェーズのタブで本文を切り替えます。初期選択はインストラクション内の要件定義です。全共通・各フェーズの本文内の既知の変数は、`{{project_directory}}` などの置換用の記法を「プロジェクトのディレクトリ」などの説明文のバッジに置き換えて表示します。保存内容やLLMへ渡すテンプレートは変更せず、未知の変数はそのまま表示します。編集用は変数を解釈せず、置換用の記法を含め原文どおり表示します。取得中と取得失敗も表示します。

根拠付きの項目がある指示では、本文中の行から原文引用と採用理由を確認できます。[要求・根拠を追跡できる文書管理](../traceable-documents-design.md)

取得APIは `GET /api/instructions` で、指示一覧、適用状態、根拠を表示するための版・項目情報を返します。適用には `POST /api/instructions/apply` を使います。本文を直接編集するフォームやHTTPの本文更新APIは設けません。

## イベント用インストラクション

`task.completed`（タスク完了）をアプリ共通で管理する。ナレッジを上層へ反映するかどうかと、その手順はこの本文に記述する。画面の「ワークフロー」で参照し、編集相談から変更する。実行時の版、権限、保存先は [イベントに対応するワークフロー](workflows.md) を参照。
