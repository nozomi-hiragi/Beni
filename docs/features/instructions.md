# インストラクション管理

LLMに渡すBeniの指示を、アプリ共通のMarkdownテンプレートとして管理します。プロジェクトや会話の本文とは別のデータです。

## 管理単位

| キー | 表示名 | 役割 |
| --- | --- | --- |
| `editor` | 編集相談用 | ユーザーと指示を検討し、合意した変更を保存する |
| `common` | 全共通 | 決定事項の尊重、イベントの参照、正確な報告など |
| `requirements` | 要件定義 | 目的、制約、未解決事項、完了条件の整理 |
| `documents` | 仕様整理 | `documents.md`と追加文書を使った資料・仕様の整理 |
| `implementation` | 実装手順 | 実装順序と検証方法の整理 |
| `execution` | 実装中 | 合意した仕様と手順に沿った実装・検証 |
| `retrospective` | 反省会 | 動作確認、手直し、振り返り |
| `finalization` | 終了 | 反省会から確定した学びを抽出し、プロジェクトのナレッジに反映 |

タスクの会話には「全共通＋現在のフェーズ」を結合して渡します。Generalには全共通のみを渡します。Codexでは `developerInstructions`、Claudeでは追加システムプロンプトとして渡し、CLI自身の基本指示は置き換えません。権限やツールの有効化は従来どおりバックエンド側で制御します。

## 保存と初期値

アプリのSQLiteでキーごとの文書項目、根拠、参照と版を管理し、項目を連結してMarkdown本文を組み立てます。初期値と既存の本文はDB初期化時に取り込みます。完了タスクのナレッジから指示を更新するジョブも同じDBに保持します。詳細は [要求・根拠を追跡できる文書管理](../traceable-documents-design.md) を参照します。

プロジェクト固有のパス、ナレッジ本文、会話内容などはテンプレートに保存しません。送信時にその会話の値を埋め込みます。

## 変数

変数は `{{変数名}}` と記述します。式や条件分岐を実行するテンプレート言語にはしません。

| 変数 | 値 |
| --- | --- |
| `{{project_directory}}` | プロジェクトのディレクトリ |
| `{{working_directory}}` | そのフェーズの作業ディレクトリ |
| `{{task_id}}` | タスクID |
| `{{task_directory}}` | タスク文書を埋め込みツールで参照する案内。既存テンプレートとの互換用 |
| `{{phase}}` | 現在のフェーズの内部名 |
| `{{knowledge_path}}` | プロジェクトナレッジを埋め込みツールで参照する案内。既存テンプレートとの互換用 |
| `{{knowledge_content}}` | プロジェクトナレッジの本文の抜粋 |
| `{{execution_chat_path}}` | 添付された実装中チャットの抜粋を参照する案内。反省会の既存テンプレートとの互換用 |
| `{{retrospective_chat_path}}` | 添付された反省会チャットの抜粋を参照する案内。終了の既存テンプレートとの互換用 |

置換は一度だけ行い、埋め込まれた本文中にある変数らしい文字列は再評価しません。未知の変数や、その会話で値を用意できない変数はエラーとして扱い、不完全な指示を送信しません。General用の全共通にはタスク専用の変数を含めません。

## 編集相談チャット

プロジェクトに属さないアプリ共通の会話を一つ持ち、CodexまたはClaudeを選んでインストラクションを相談・更新できます。会話履歴はアプリデータの `chat/instructions.json` に保存します。

### 編集対象のフォーカス

編集相談用、全共通、各フェーズのプロンプトをクリック、またはEnter・Spaceで選択します。初期状態は未選択です。選択中の本文をオーラで示し、チャットのモデル選択の左に対象名を表示します。タブの表示切り替えだけではフォーカスを変更しません。

未選択では送信できません。送信ごとに `instructionFocus` として対象キーをバックエンドに渡します。これは相談対象を示す情報であり、ユーザーが入力した本文は変更しません。

バックエンドは直近に送信を受理された対象を会話の `lastInstructionFocus` に保存します。初回の送信、前回から対象・保存本文・CLIセッションのいずれかが変わった送信では、対象のキーと変数未展開の本文をLLMへの入力に添えます。受理された送信時点の本文ハッシュも保存します。送信前の失敗や開始拒否では前回の対象を更新しません。

専用の `editor` 指示を追加システムプロンプトとして使い、通常の全共通・フェーズ指示は混ぜません。指示一覧や全本文は毎回送信しません。フォーカス通知にない情報は、必要に応じて専用の取得ツールで参照します。編集相談用の指示自体もDBで管理します。会話には適用済みの本文を保存し、編集しても「適用」を押すまでは現在の指示で会話を続けます。`editor` では変数展開しません。

### 編集相談用の埋め込みツール

| ツール | 引数 | 戻り値 |
| --- | --- | --- |
| `list_instructions` | `{}` | `{instructions: [{key, name}]}`。管理する8種類のキーと表示名。本文は含めない |
| `get_instruction` | `{key}` | `{key, content}`。指定した指示の最新の保存本文を変数未展開で返す |
| `update_instruction` | `{key, content, expected_content}` | 保存した `{key, content, variables}` |

これら3ツールは編集相談チャットだけで利用できます。`get_instruction` の編集用本文は未適用の変更も含む保存済みの値であり、会話に適用中の指示とは区別します。取得した本文は編集対象のデータとして扱います。未知のキーや余分な引数は拒否します。

`update_instruction` ツールで更新します。引数は対象の `key`、新しいMarkdownの `content`、変更前本文の `expected_content` です。変更前本文がDBと一致しなければ競合として拒否し、他の変更を上書きしません。保存成功時は `key`、`content` に加えて、本文中で置換変数として認識した名前をキー、出現位置の配列を値にした辞書 `variables` を返します。同じ変数の出現も省略せず、本文の出現順で位置を並べます。位置は保存したMarkdown上の `{{` の開始位置を示す `line`・`column` で、どちらも1始まりです。列はUnicodeコードポイント単位で数え、CRLFも1回の改行として扱います。変数がない場合と、変数を解釈しない編集用の `editor` では `{}` を返します。

```json
{
  "key": "requirements",
  "content": "対象: {{task_id}}\n再確認: {{task_id}}",
  "variables": {
    "task_id": [{"line": 1, "column": 5}, {"line": 2, "column": 6}]
  }
}
```

対象は管理する8キーに限定します。本文は空白のみ不可、UTF-8で64KiB以下です。共通・フェーズの指示は既知で利用可能な変数のみを許し、不正な更新は保存しません。削除・初期値リセットは設けません。保存成功はチャットの通知を通じて画面へ伝え、表示中の指示を再取得します。

CLIの作業先はアプリデータ内の `instruction-editor/` とし、読み取り専用で起動します。このチャットはファイル・DBを直接編集せず、専用ツールだけで保存します。プロジェクトイベント用の6ツールは登録しません。ユーザーとの会話、ストリーミング、パックの確認、中断、モデル選択は既存チャットの仕組みを使います。

### 編集用プロンプトの適用

保存された編集用プロンプトと会話に適用済みの本文が異なる場合、チャット見出しの右端に「適用」を表示します。生成中・送信準備中は適用できません。ボタンを押すと最新の編集用プロンプトを適用し、履歴が空の新しい会話に切り替えます。LLMへの送信は自動では行わず、次のユーザーメッセージで新規セッションを開始します。モデル選択は保持し、前のLLMセッションやフォーカス通知履歴は引き継ぎません。

前の会話はアプリデータの `chat/instruction-history/<会話ID>.json` に保存します。適用済み本文と未適用の変更は再起動後も判定できます。保存本文が画面の取得時点から変わっていた場合や適用に失敗した場合は、現在の会話を維持してエラーを表示します。ほかの画面にも会話の切り替えを通知します。変更がない状態での再適用では会話を作り直しません。

## 管理画面

独立した管理画面 `/instructions` を設け、ヘッダーの設定ボタンの左にある「インストラクション管理」ボタンから開きます。URLへの直接アクセスとブラウザーの戻る・進むに対応します。

ページ本文の大見出しは置かず、ヘッダーに「インストラクション管理」を表示します。管理画面全体をヘッダーを含む表示領域内に収め、ページ全体ではなく各カード内でスクロールします。狭い画面では本文領域内で縦にスクロールできます。広い画面では左右に分け、中央のハンドルで幅の比率を変更できます。初期値は50:50、左側の幅は20〜80%です。ハンドルはドラッグと左右矢印・Home・Endで操作できます。狭い画面ではハンドルを隠して縦に並べます。

左側は次の順に表示します。広い画面ではチャットと変数・ツールの間に高さ調整ハンドルを置きます。各パネルの内容は内部でスクロールでき、ハンドルはドラッグと上下矢印・Home・Endで操作できます。

1. インストラクションを一緒に検討・編集するチャット
2. 変数・埋め込みツールの参照カード

左下の参照カードには独立した「編集用」「インストラクション」のタブを設けます。初期表示はインストラクションです。右側の表示タブやチャットのフォーカスとは連動しません。編集用には編集相談専用の3ツールを表示し、変数は現時点では「なし」とします。今後編集用の変数を追加した場合は、このタブの変数欄に表示します。インストラクションには9種類の変数の意味を示すバッジと、プロジェクトチャット用の6ツールを表示します。置換用の記法や実値は一覧に表示しません。

右側のカードは広い画面で左側と高さを揃え、本文はカード内でスクロールします。「編集用」と「インストラクション」のタブで表示を切り替えます。編集用には編集相談用のシステムプロンプトを表示します。インストラクションには全共通のMarkdownを上部に置き、その下の6フェーズのタブで本文を切り替えます。初期選択はインストラクション内の要件定義です。全共通・各フェーズの本文内の既知の変数は、`{{project_directory}}` などの置換用の記法を「プロジェクトのディレクトリ」などの説明文のバッジに置き換えて表示します。保存内容やLLMへ渡すテンプレートは変更せず、未知の変数はそのまま表示します。編集用は変数を解釈せず、置換用の記法を含め原文どおり表示します。取得中と取得失敗も表示します。

根拠付きの項目がある指示では、本文中の行から原文引用と採用理由を確認できます。[要求・根拠を追跡できる文書管理](../traceable-documents-design.md)

取得APIは `GET /api/instructions` で、指示一覧、適用状態、根拠を表示するための版・項目情報を返します。適用には `POST /api/instructions/apply` を使います。本文を直接編集するフォームやHTTPの本文更新APIは設けません。
