# DummyAgent 仕様

[Agent インターフェース](README.md) を実装するテスト用 Agent。既定の登録 ID は `dummy`。試験ごとに別の ID とシナリオを指定できる。通常起動の登録一覧には含めない。

## 入力と動作

- テストが渡したシナリオに従って、受け取った `AgentRequest`、イベント、終了結果を扱う。既定の状態は `ready`、認証は `not-required`、モデルは固定の `dummy-model`。利用枠取得・コマンド・埋め込みツールは試験に必要なときだけ設定する。
- `new` はテスト内で再現できるセッション ID を発行し、`resume` はそのインスタンスが保持するセッションを再開する。存在しない再開先は `session-missing` を返す。`ephemeral` では再開情報を保持しない。
- シナリオは本文差分、確定本文、ツールの開始・終了、利用枠通知、受理前の拒否、実行失敗、結果不明を返せる。中断試験ではテストが実行を待機させ、`AbortSignal` を受けて停止するか、停止を確認できない結果を返す。実時間の待ち合わせに依存しない。
- 外部 SDK・CLI・認証・ネットワーク・シェル・プロジェクトファイルへの直接アクセスは使わない。ツールを試験する場合は、Beni が登録したツールを `AgentHost.callTool` で呼ぶ。

## 確認するケース

| ケース | 検証する Beni の動作 |
| --- | --- |
| 受理・複数差分・確定 | ユーザー発言の先行保存、パックの逐次更新、確定本文、終了状態 |
| 再開・別 ID への切り替え | 履歴を保持し、セッションと引き継ぎ位置を Agent ID ごとに分離する |
| 再開先の消失 | 受理前に確定した消失では一度だけ新規セッションを開始する |
| 一時セッション・保守 | 一時実行のセッションを会話に保存せず、保守の出力を通常の応答パックと分ける |
| モデル拒否・中断・切断 | 各終了状態を区別し、結果不明の自動再送を防ぐ |
| 埋め込みツール | 対象範囲内での実行、無効な入力の拒否、終了後の呼び出しの拒否 |
| 任意機能の有無 | 登録された機能に応じたコマンド・利用枠の扱い |

DummyAgent は Beni の共通処理を検証する。Codex の JSON-RPC や Claude SDK と CLI の接続を検証するときは、既存の `fake-codex.ts` と `fake-claude.ts` を使う。
