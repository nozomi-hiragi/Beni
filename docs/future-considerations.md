# 今後の検討事項

この文書は、全体仕様から分離した未決定の構想を記録する。採用、実装時期、具体的な方式は確定していない。採用する際は関連する仕様書で挙動と条件を定義する。[Beni全体仕様](specification.md) を参照。

## 実行の監修と質問

- 要件定義を軽量モデル、計画・監修を高性能モデルに分担し、フェーズ切り替え時に対話担当を判断する構成。ユーザーによるモデル選択との関係は別途定義する。
- 高性能モデルがサブエージェントへの割り当て、監視、レビュー、添削を行う構成。
- 実行中に質問を表示し、回答待ちの作業を止めながら依存しない作業を並行して進める仕組み。採用する場合は、実装中の入力を受け付けない現行仕様との関係を定義する。
- 選択肢、数値、日付、シークレットなどの専用入力部品。シークレットを扱う場合は入力を伏せ、チャット履歴やMarkdownに値を表示しない。保存・接続先への受け渡し方法は別途決める。
- 開始時に指示書・計画の版とユーザーの承認を関連づけて保存し、変更時に再確認の要否を判断する仕組み。

## 判断と権限の改善

ユーザーのフィードバックから、任せてよいことと確認が必要なことを「権限MD」にまとめる構想。ユーザーの判断とモデルの提案を区別する方針は維持し、権限の適用範囲、確認方法、既存の実行制限との関係は別途決める。

## ナレッジの自動整理

- 指示、行動、質問と回答、修正指示、結果をナレッジDBで関連づけ、緊急度や手戻りの原因を分析する。
- 記録から複数の手順書を作成・監修し、次のタスクで必要なものを選んで参照する。スキルやMCPを使うかも未決定。
- フェーズ切り替え時に未反映の知見を確認し、タスク終了時を基本に、緊急度、未反映量、コスト、利用枠に応じて整理の時期を調整する。
- 指示・返答の時刻と内容から稼働傾向を推定し、ユーザープロファイルMDへ反映する。ユーザー不在時の整理や利用枠の配分も検討する。収集範囲、保持方法、分析指標は未決定。
- 分析手法自体をMarkdownに記録し、改善する。管理単位は未決定。
- ナレッジ、手順書、権限MDなどをGitで管理し、モデルが整理・コミットする。採用時には対象と実行条件を定義する。
- 反映済みの記録の圧縮・アーカイブ・削除。根拠の追跡方法と保存期間は未決定。

現行のタスク文書、ナレッジ、インストラクションの参照関係は [要求・根拠を追跡できる文書管理](traceable-documents-design.md) を参照。
