# プロジェクト

プロジェクト情報はアプリデータ内で管理し、作業フォルダーをID指定で再設定します。[保存先・識別・再指定](../data/storage.md)

プロジェクトは、IDで識別する作業と保存データの単位とする。ID・名前・作成日時・更新日時と作業フォルダーの対応は、アプリDBの `projects` に保存する。プロジェクトDBには所属IDを保持し、登録と保存領域を照合する。

## 持ち物

| 持ち物 | 数 | 用途 |
| --- | --- | --- |
| [タスク](task.md) | 0件以上 | このプロジェクトで進める個々の依頼 |
| [ターミナル](terminal.md) | 0個以上 | このプロジェクトの作業フォルダーで使うセッション |
| ナレッジ | 0または1件 | DB文書 `knowledge.md`。次のタスクに引き継ぐプロジェクト共通の学び |
| [Generalチャット](chat.md) | 1つ | プロジェクト全体の会話。各タスクの会話はそのタスクに属する |

## プロジェクトの操作

| 操作 | 可否と操作場所 |
| --- | --- |
| 作成 | 可：ホーム → プロジェクト選択 →「新規プロジェクト作成」で作業フォルダーを登録する。初回はBeniが初期化し、既存のプロジェクト情報があれば引き継ぐ |
| 閲覧 | 可：ホームのプロジェクト選択から開く |
| 更新 | 可：ホームで既存プロジェクトを選び「作業フォルダーを変更」から登録先を更新する。画面からの改名は不可 |
| 削除 | 不可：登録の解除やフォルダーの削除を行う画面操作はない |

作業フォルダーを再指定しても、同じプロジェクトIDと保存データを引き継ぐ。

## ナレッジ

終了フェーズで、反省会から得たプロジェクト共通の学びを DB文書 `knowledge.md` に保存する。タスク固有の詳細は各タスクの `retrospective.md` に残す。次回のタスクで参照し、既存の知識を尊重して更新する。共通化できる行動ルールはBGでインストラクションへ反映する。タスク削除では共通知識を削除せず、作業フォルダーの移動・消失後も保持する。
