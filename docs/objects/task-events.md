# タスクの変更履歴

タスクの変更はプロジェクト共通のイベント履歴に属する。タスク文書・ツール実行・フェーズ変更などを、タスクとフェーズで絞り込んで参照する。Generalや各フェーズのチャットは埋め込みツールを使い、必要なイベント・差分・過去の版を取得する。

- 記録対象とタスク削除後の扱い：[プロジェクトイベント](../project-events/README.md)
- SQLite・差分・全文キャッシュ：[保存形式](../project-events/storage.md)
- 取得ツールと確認完了：[埋め込みツール](../project-events/tools.md)

## チャットへの引き継ぎ

送信時にプロジェクトイベントの末尾を固定し、その会話の確認済み位置と今回の上限をエージェントへ知らせる。イベント本文はユーザー発言へ混ぜず、必要な履歴を埋め込みツールで取得する。

会話JSONの `lastEventId` は、LLMが確認完了を通知したプロジェクトイベントの上限ID。初期値は0。送信受付・取得・生成完了だけでは進めない。確認完了なしで停止した場合は次の送信でも未確認範囲を知らせる。

フェーズ変更で文書やイベントは巻き戻さない。変更元が特定できない編集は、表示中のフェーズを変更元と推測しない。

## 取得と通知の契約

`GET /api/tasks/:id/events` は `projectId` と `after`（既定0）、任意の `through`、`limit`（1〜100、既定100）を受け取り、そのタスクのイベントを返す。IDと範囲はプロジェクト全体で共有する。ページ取得は同じ `through` で固定し、後続ページには `nextCursor` を使う。別タスクのイベントによる飛び番を許容する。

`GET /api/tasks/:id/events/versions/:hash?projectId=...` は、そのタスクの履歴から参照される本文を復元して `{version, content}` で返す。タスク削除後もプロジェクト内の履歴を取得できる。

WSの `task-events` トピックは `{projectId, taskId}` を対象とし、`task.events.changed` の `{lastEventId}` で変更を通知する。通知は再取得のきっかけであり、保存済みイベントや本文を代替しない。
