# タスク

一つのプロジェクトに属する依頼。タスクIDで識別し、名前・フェーズ・状態・作成日・更新日を持つ。

## 持ち物

| 持ち物 | 数 | 用途 |
| --- | --- | --- |
| [タスクチャット](chat.md) | 各フェーズに1つ、計4つ | フェーズごとに発言・返信と接続先の会話を分ける |
| [変更イベント履歴](task-events.md) | 1つ | タスク文書とフェーズの変更を全フェーズで共有する |
| 文書の版履歴 | 文書の各版 | 変更前後の本文を後から確認できるように保存する |
| 標準文書：要件定義 | 1件 | `requirements.md`。何を実現するか、どんな条件を満たせば完了かを書く |
| 標準文書：仕様整理 | 1件 | `documents.md`。整理対象ごとに作成した追加MDへのリンクを「資料」「仕様」に分けて載せる |
| 標準文書：実装手順 | 1件 | `implementation-plan.md`。要件をどのような手順で実装・確認するかを書く |
| 追加文書 | 0件以上 | 整理対象ごとに作るMarkdown。各ファイルは「資料」「仕様」のどちらか一方に属する |

固定の標準文書3件と可変の追加文書を合わせて「タスク文書」と呼ぶ。すべて同じタスクに属し、そのタスクの文書ツリーから開ける。[文書タブの表示名と保存名](../screens/project-detail.md#フェーズと文書タブの表示名)

## 仕様整理で作る追加文書

要件定義の後、実装手順を立てる前に、詳しく整理する対象を洗い出す。対象ごとにタスク内でMDファイルを作り、仕様整理の固定MDから各ファイルへ相対リンクを張る。固定MDは追加文書の目次として使う。`documents.md` の「資料」「仕様」見出し配下の相対リンクで分類を表し、同じ追加文書を両方に載せない。

| 分類 | 書く内容 | 実装中の扱い |
| --- | --- | --- |
| 資料 | 調査結果、現状の挙動、比較した案など、作業中の判断に使う情報 | タスク内だけに置く |
| 仕様 | 採用する挙動・条件などの確定内容。タスクの会話を知らない読者にも、そのままリポジトリの文書として通じる粒度で書く | 作業対象リポジトリのドキュメントに配置する |

たとえばAPIを変更するタスクなら、目次の「資料」には現行APIの調査メモを、「仕様」には変更後の入出力とエラー条件を記した文書をリンクする。実装中にリポジトリへ配置するのは後者。

## フェーズの進行

「要件定義 → 仕様整理 → 実装手順 → 実装中」の順に進む。文書を確認して「確定」を押すと次の整理フェーズへ進み、実装手順の「実行指示」で実装中へ進む。フェーズの文書を開く操作と、フェーズを進める操作は別に扱う。「戻る」で直前のフェーズの会話を再開できる。戻る操作では文書・会話・実装済みコードを巻き戻さない。実装中から戻った後の依頼は、再びタスク文書だけを編集対象にする。チャット実行中は前後どちらにも変更できず、古い画面からの重複操作で次の段階を飛ばさない。

最初の3フェーズではタスク文書を編集する。実装中に送信した依頼では、作業対象プロジェクトを編集できる。エージェントは目次の「仕様」をリポジトリの文書として配置し、実装手順に沿って作業する。配置先では既存文書との整合を取り、資料はタスク内に残す。フェーズ変更だけではエージェントへの自動送信は行わない。

## タスクの操作

| 操作 | 可否と操作場所 |
| --- | --- |
| 作成 | 可：ホーム → プロジェクトと名前を指定 → タスク作成。文書だけ残ったタスクは自動復元 |
| 閲覧 | 可：ホームの一覧・検索、プロジェクトのタスクツリー・タブ |
| 更新 | 可：タスクタブを右クリック → リネーム → Enter。会話・文書の変更時は更新日を自動更新 |
| 削除 | 可：タスクタブを右クリック → 削除 → 対象名を確認してOK。実行中のタスクチャットは終了後に操作 |

## タスク文書（Markdown）の操作

| 操作 | 可否と操作場所 |
| --- | --- |
| 作成 | 自動：タスク作成時に標準文書を各1件用意する。仕様整理で対象ごとの追加文書を作成し、目次にリンクする |
| 閲覧 | 可：プロジェクト → 文書ツリー・プレビュー |
| 更新 | 依頼：タスクチャットから本文を更新。ファイルのリネームは予定 |
| 削除 | 自動：タスク削除時に配下の文書も削除。文書単独の削除ボタンは不可 |

タスクタブや文書タブの「×」は、その画面を閉じる操作。タスク本体を削除すると配下の文書とタスク会話が削除される。移行時のバックアップと旧履歴アーカイブは別管理とする。

文書のリネームは実装予定。操作場所を文書タブと文書ツリーのどちらにするか、固定名の標準文書3件も対象にするかは未決。
