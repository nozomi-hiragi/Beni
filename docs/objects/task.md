# タスク

一つのプロジェクトに属する依頼。タスクIDで識別し、名前・フェーズ・状態・作成日・更新日を持つ。

## 持ち物

| 持ち物 | 数 | 用途 |
| --- | --- | --- |
| [タスクチャット](chat.md) | 各フェーズに1つ、計6つ | フェーズごとに発言・返信と接続先の会話を分ける |
| [変更イベント履歴](task-events.md) | プロジェクト履歴の一部 | タスク文書と操作・フェーズ変更を共有し、タスク削除後も保持する |
| 文書の版履歴 | 文書の各版 | 変更前後の本文を後から確認できるように保存する |
| 標準文書：要件定義 | 1件 | `requirements.md`。何を実現するか、どんな条件を満たせば完了かを書く |
| 標準文書：仕様整理 | 1件 | `documents.md`。整理対象ごとに作成した追加MDへのリンクを「資料」「仕様」に分けて載せる |
| 標準文書：実装手順 | 1件 | `implementation.md`。要件をどのような手順で実装・確認するかを書く |
| 反省会の記録 | 0または1件 | `retrospective.md`。反省会に進んだ時点で用意し、確認結果・手直し・次回への学びを記録する |
| 実装担当モデル | 0または1つ | チャット用とは別に、タスク単位でフロントエンドに記憶する |
| 追加文書 | 0件以上 | 整理対象ごとに作るMarkdown。各文書は「資料」「仕様」のどちらか一方に属する |

固定の標準文書3件、反省会の記録と可変の追加文書を合わせて「タスク文書」と呼ぶ。すべて同じタスクに属し、そのタスクの文書ツリーから開ける。[文書タブの表示名と保存名](../screens/project-detail.md#フェーズと文書タブの表示名)

## 仕様整理で作る追加文書

要件定義の後、実装手順を立てる前に、詳しく整理する対象を洗い出す。対象ごとにDB文書を作り、仕様整理の目次から各文書名へ相対リンクを張る。固定MDは追加文書の目次として使う。`documents.md` の「資料」「仕様」見出し配下の相対リンクで分類を表し、同じ追加文書を両方に載せない。

| 分類 | 書く内容 | 実装中の扱い |
| --- | --- | --- |
| 資料 | 調査結果、現状の挙動、比較した案など、作業中の判断に使う情報 | タスク内だけに置く |
| 仕様 | 採用する挙動・条件などの確定内容。タスクの会話を知らない読者にも、そのままリポジトリの文書として通じる粒度で書く | 作業対象リポジトリのドキュメントに配置する |

たとえばAPIを変更するタスクなら、目次の「資料」には現行APIの調査メモを、「仕様」には変更後の入出力とエラー条件を記した文書をリンクする。実装中にリポジトリへ配置するのは後者。

## フェーズの進行

準備中は「要件定義」「仕様整理」「実装手順」のフェーズ名をクリックして自由に切り替える。選択したフェーズの会話と対応文書を開く。「確定」「戻る」は設けない。文書タブの選択は文書の表示だけを変える。

`implementation.md` の本文が初期テンプレートから編集されていれば「開始」を有効にする。時刻の変更や初期ファイルの補完だけでは有効にせず、空の本文・初期テンプレートへ戻した本文も開始不可とする。導入前から内容のある実装手順も対象とし、サーバーで開始直前に再検証する。

準備フェーズでは「開始」の横に実装担当モデルのプルダウンを表示する。選択はタスク単位でフロントエンドに記憶し、フェーズごとのチャット用モデルとは独立させる。接続先とモデルIDを区別し、利用不可なら `⚠️` を表示して開始を無効にする。

開始すると実装担当モデルへ、実装手順に従ってゴールまで実装・検証を完走する定型依頼を送る。実装中はユーザーの入力・送信・モデル変更・フェーズ切り替えを禁止し、進捗を閲覧する。操作は「停止」のみ。停止は実際の作業停止を待ち、「実装手順」へ戻す。停止に失敗した場合は実装中のままとし、動作が続いているのに準備中と表示しない。

LLMの実行が終了したら自動で「反省会」へ進む。正常終了はユーザーが期待するゴールの達成を保証しない。生成失敗や接続終了で結果不明になった場合も、未達を確認・追求できるよう反省会へ進む。ツール一つの終了やブラウザーの通信切断だけでは遷移しない。明示的な停止処理中は自動遷移せず、停止の遷移を優先する。送信受け付け前の失敗は開始前のフェーズへ戻す。

反省会へ進んだ後は、フェーズ欄の「実装中」をクリックして実装時のチャット履歴を閲覧できる。「反省会」をクリックすると反省会の会話へ戻る。この切り替えは表示だけを変え、タスクのフェーズ・状態や文書の表示を変更しない。実装履歴には入力できず、タスク完了後も閲覧できる。反省会でのチャット実行中やフェーズ更新中は閲覧先を切り替えない。終了の処理中も、実装中・反省会・終了の履歴を選んで閲覧できる。

フェーズの切り替えや停止で文書・会話・実装済みコードを巻き戻さない。準備中のチャット実行中はフェーズ変更と開始を拒否し、古い画面からの操作は現在フェーズとの一致を確認する。

最初の3フェーズではタスク文書を編集する。実装中と反省会ではプロジェクト内を編集できる。実装では目次の「仕様」をリポジトリの文書として配置し、既存文書との整合を取る。「資料」はタスク内に残す。仕様整理と実装手順への遷移で、先行文書に基づく文書作成を始める。

## 反省会と終了

ユーザーが動作確認し、未達・不具合・意図とのズレを専用チャットで追求する。手直しと検証もここで依頼できる。仕様策定で察せなかったこと、書き出せなかった条件や確認不足を振り返り、事実・原因・次回の改善を `retrospective.md` に整理する。推測を確定したユーザーの意図として記録しない。

自動精査の待機中・実行中はチャット入力を止める。失敗した精査は画面から再試行できる。精査が完了し、チャットの処理が止まっているときに「タスク完了」で終了へ進む。終了用の定型依頼には反省会で最後に送信したモデルを使い、送信履歴がなければ既定の接続先・モデルを使う。

終了では反省会の会話と `retrospective.md` を参照し、再利用できる確定した学びをプロジェクト共通のDB文書 `knowledge.md` に反映する。既存の知識を尊重し、新しい学びがなければ更新しない。タスク固有の経緯はタスク内に残す。別プロジェクトには自動共有しない。[プロジェクトのナレッジ](project.md#ナレッジ)

終了のチャットは進捗と履歴の閲覧専用とする。入力・送信・中断・モデル変更は受け付けない。ナレッジ版を確定するとタスクを完了し、BGでインストラクションを更新する。ナレッジを確定できなかった場合は終了の会話を保持し、反省会へ戻す。

完了後の「再開」で同じタスクの反省会へ戻る。終了・反省会・実装中の会話は保持する。従来の仕様で反省会のまま完了したタスクも、同じ操作で再開できる。

## タスクの操作

| 操作 | 可否と操作場所 |
| --- | --- |
| 作成 | ホームでプロジェクトと名前を指定し「タスク作成」を押す。旧 Markdown が残っているタスクは自動復元の対象になる |
| 閲覧 | ホームの一覧、プロジェクトのタスクツリー・タブから開く |
| 更新 | 可：タスクタブを右クリック → リネーム → Enter。会話・文書の変更時は更新日を自動更新 |
| 削除 | 可：タスクタブを右クリック → 削除 → 対象名を確認してOK。実行中のタスクチャットは終了後に操作 |

## タスク文書（Markdown）の操作

| 操作 | 可否と操作場所 |
| --- | --- |
| 作成 | 自動：タスク作成時に標準文書を各1件用意する。仕様整理で対象ごとの追加文書を作成し、目次にリンクする |
| 閲覧 | 可：プロジェクト → 文書ツリー・プレビュー |
| 更新 | 依頼：タスクチャットから本文を更新。ファイルのリネームは予定 |
| 削除 | 自動：タスク削除時に配下の文書も削除。文書単独の削除ボタンは不可 |

タスクタブや文書タブの「×」は、その画面を閉じる操作。タスク本体を削除すると配下の文書とタスク会話が削除される。

文書のリネームは実装予定。操作場所を文書タブと文書ツリーのどちらにするか、固定名の標準文書3件も対象にするかは未決。
