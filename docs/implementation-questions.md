# 実装前の確認事項と確定した方針

確認への回答を反映した実装仕様です。初期のデスクトップGUI・Webhook案は、以下のCLI・ポーリング構成に変更しました。

| 項目 | 確定した方針 |
| --- | --- |
| 1. OS | Bunで動作させる。OS固有処理はまずmacOSで確認する。 |
| 2. 技術 | 既存のBun、TypeScript、Linear SDK、Codex SDKを使用し、必要な実装判断は開発側で行う。 |
| 3. 依頼の受信 | Webhookを受けず、PCからSession・Activityをポーリングする。初期間隔15秒で設定可能。Webhook未設定でのSession自動生成は実接続で検証し、成立しなければ受信方式を再検討する。 |
| 4. Linear認証 | 利用者自身のOAuthアプリを使う。1ワークスペース・1端末を初期範囲とする。PKCEとlocalhostコールバックを使い、トークンはOS資格情報ストアへ保存する。 |
| 5. Codex | 端末で認証済みの環境を使用する。モデルは既存設定を尊重し、必要なら設定ファイルで指定する。 |
| 6. 対象プロジェクト | 対象リポジトリのルートで起動するか、引数でパスを渡す。Linearプロジェクトとの対応を設定ファイルに記載する。 |
| 7. Git | 親イシューのブランチへ、サブイシューのブランチをローカルで統合する。全工程完了後に親ブランチを人がレビューする。GitHubへのpush・PR作成は行わない。実行用worktreeとローカルcommitを使う。 |
| 8. 実行権限 | 承認後は対象作業領域の変更、コマンド実行、依存取得・資料参照のネットワーク利用を許可する。計画段階は読み取りのみ。 |
| 9. 実行上限 | 同一リポジトリは直列、別リポジトリは最大2件。1工程30分、追加情報取得10回を初期値とし、設定ファイルで変更可能。 |
| 10. 承認者 | 計画承認・変更・再開は依頼者。停止はSession参加者から受け付ける。 |
| 11. 復旧 | 実行途中で終了した工程は、再起動後に明示的な再開指示を待つ。 |
| 12. 起動形態 | コンソールで継続実行する。GUIは作らず、デーモン化は必要性が生じた場合に検討する。 |
| 13. 保存 | 復旧・重複排除・実行に必要な最小状態と計画を保持する。会話・全イベントを複製せず、初期版では完了記録の自動削除は行わない。 |
| 14. 検証 | 一時Gitプロジェクトによるテストに加え、実際のCodex・Linear接続を試す。確認用プロジェクトの作成は許可済み。 |

## 受信方式についての合意

ポーリング方式はユーザーが明示的に選択した検証対象です。停止検知にもポーリング間隔とAPI応答時間の遅延があります。Linearはポーリングを推奨していないため、API制限時は取得を停止して待機します。Webhook時の10秒以内の応答要件を満たす保証はありません。

Session一覧とActivity取得APIはSDKの型で確認済みです。APIが存在することと、Webhook未設定でメンション・委任から自動生成されることは別に検証します。

## 運用上の境界

- 通常運転に公開HTTPポートは不要。認証時だけ127.0.0.1で一時的にコールバックを受ける。
- 追加・計画外の作業は新しい計画として再承認を求める。
- 親イシューは自動完了しない。
- Codexが権限不足や追加要件に遭遇した場合は停止し、サンドボックスを自動解除しない。
- Beni自身の今回の開発では、明示的な依頼なしにcommit・push・PR作成を行わない。
- 実際の接続先ID、個人情報、非公開URL、資格情報は公開リポジトリに記録しない。
