# Beni

複数のコーディングエージェントを使い、依頼から計画・実行・監修までを支援するアプリケーションです。

## 起動

[Bun](https://bun.sh/) を用意して、このディレクトリで実行します。

```sh
bun install
bun run start
```

起動時に SolidJS の TypeScript と Tailwind CSS・daisyUI のスタイルをビルドします。

ブラウザーで http://127.0.0.1:3210/ を開きます。ポートは `BENI_PORT`、データベースの保存先は `BENI_DB` で変更できます。既定では作業ディレクトリの `beni.sqlite` に保存します。会話は平文で保存されるので、秘密情報を入力しないでください。

## 現在の機能

プロジェクトの名前とフォルダの登録、タスク作成、タスク別の会話保存、初期指示書の表示に対応しています。フォルダの登録はパスの記録のみです。タスクの指示書は名前から初期化し、会話からの自動更新はまだ行いません。

LLM、認証、利用枠、計画・実行、ターミナル、Gemma を使った検索は未接続です。検索は現在、タスク名と ID の簡易検索です。

指示書・計画の生成、承認、担当実行、監修、履歴、結果不明時の確認を扱う API の基盤があります。タスクへのユーザー発言は原文と関連する履歴を保存します。外部接続は設定されておらず、画面からこれらの操作はまだできません。手直し指示と実行の関連付けは内部 API のみで、画面や HTTP からは利用できません。指示書内の未決事項の個別管理・解決は未実装です。

監修が失敗・中断・旧版となった場合、そのまま同じ計画を再承認・再実行することはできません。ユーザーの新しい指示を受け、新しい計画を作成して承認してから進めます。監修中の追加指示によって旧版となった場合は、既に受けた指示を使えます。新計画には監修の失敗・中断・旧版の記録を渡します。監修結果の確認・再試行専用の操作は未実装です。

処理中の復旧を防ぐ仕組みは同じサーバープロセス内に限られます。同じデータベースを複数のサーバープロセスで同時に使わず、実際のエージェントへ接続する前にプロセス間の安全性を整える必要があります。直接内部クラスを使う場合も同様のガードが必要です。複数の SQLite 接続を使うためインメモリ DB は利用できず、ハードリンクされた DB は起動時に拒否します。シンボリックリンクは実体のパスに解決します。
